# BraidPath 0.7.4

- Ordinary SOCKS5 UDP uses a dedicated HTTP/3 stream on each path. Ordered delivery per destination is preserved. Short gap repairs can take the DATAGRAM lane, and retained records can move to a healthy path when a link stalls.
- Sustained ordinary UDP queues now use observed payload acknowledgments to adjust the affected path's pacing. Native TCP downloads use bounded path queues and account for estimated completion time when scheduling bulk data.
- One proxy client can expose ordinary SOCKS5, Game SOCKS5, and fixed TCP listeners. Ordinary and Game listeners use independent mesh sessions.

Upgrade servers and clients together. Upgrade servers first, then start the new clients as soon as their exits are ready. Ordinary SOCKS5 UDP uses a new wire carrier and requires 0.7.4 at both endpoints. Existing mesh identities can be reused. For explicit ordinary listeners, remove `--game-mode off` and keep `--socks5 EXIT=ADDRESS`. For explicit Game listeners, replace `--game-mode on --socks5 EXIT=ADDRESS` with `--game-socks5 EXIT=ADDRESS`. For Game listeners configured with `--exit` and `--listen`, use `--game-exit` and `--game-listen`.

## 中文说明

- 普通 SOCKS5 UDP 在每条路径上用独立 HTTP/3 流传输，仍按目的地可靠、有序交付。短缺口可用 DATAGRAM 补发，路径失速时可把未确认的数据改派到健康路径。
- 普通 UDP 持续排队时，按实际确认的交付速率调整该路径发送节拍。原生 TCP 下载按预计完成时间分配数据，并限制各路径的待发队列。
- 同一个代理客户端可提供普通 SOCKS5、Game SOCKS5 和固定 TCP 监听。普通和 Game 监听分别使用独立的聚合会话。

请配套升级服务端和客户端。先更新服务端，相关出口就绪后立即切换客户端。普通 SOCKS5 UDP 的承载格式有变化，要求两端都使用 0.7.4。现有身份和成员配置可以继续使用。显式普通监听删除 `--game-mode off`，继续使用 `--socks5 EXIT=ADDRESS`。显式 Game 监听把 `--game-mode on --socks5 EXIT=ADDRESS` 换成 `--game-socks5 EXIT=ADDRESS`。如果 Game 监听使用 `--exit` 和 `--listen`，请改用 `--game-exit` 和 `--game-listen`。
