# BraidPath v0.7.0

## Changes

- **Adaptive forwarding.** The unified `proxy-client` defaults to native HTTP/3 return
  streams for bulk TCP data. The receiver processes application DATAGRAMs
  while waiting for native admission and decodes each native TCP record once.
  Uploads, stream acknowledgments, resets and UDP use the DATAGRAM carrier.
- **Game mode.** In the unified client, `--game-mode on` prioritizes UDP with
  the Game scheduler and checks the local send deadline
  through Quinn admission. Locally discarded frames stay out of network-loss
  samples. The deadline covers local queueing and Quinn admission.
- **Reliable forwarding.** Native QUIC owns loss recovery while its path remains
  responsive. If the path fails or loses ACK progress, retained TCP offsets
  return to stream recovery.

Use `--game-mode off` to select the default policy explicitly. Run separate unified
clients for different policies. For Game
sessions with concurrent large TCP uploads and downloads, start with explicit
directional ceilings appropriate to the link. Set the client ceiling with
`--rate-bps` and the server ceiling with `--max-rate-bps`. Check complete UDP
delivery and tail latency when evaluating automatic rates.

## Upgrade

1. Upgrade participating BraidPath clients and servers together. The 0.7 line
   uses BQ2C quality feedback and retains the BQ3C capacity-probe container.
   Deploy 0.7 peers together with their existing identity files.
2. Remove `--legacy-recovery`, `--rtt-source-baselines`,
   `--random-loss-service`, `--queue-gated-loss` and
   `--experimental-socks5-early-reply` from service definitions. The standard
   SOCKS connection behavior and `--socks5-wait-for-connect` remain available.
3. Move offline transfer tools to structured snapshots. The earlier independent
   transport log parser and BQ1C feedback support have been removed.
4. Validate the release bundle against `SHA256SUMS` and follow the
   [installation guide](../install.md).

## 中文说明

- 统一客户端默认用原生 HTTP/3 回程传送大块 TCP 数据，等待接收额度时仍处理
  DATAGRAM。原生 TCP 数据只解码一次。
- 统一客户端用 `--game-mode on` 开启 Game，`--game-mode off` 使用默认策略。
  Game 优先处理 UDP，期限覆盖本地排队至 Quinn 准入，本地丢弃单独统计。
  游戏与大流量并发时，可按链路容量设置客户端上行和服务端下行上限。
- 不同策略各用一个统一客户端实例。升级时一并更新客户端和服务端，
  沿用已有身份文件，并清理服务定义中的退役参数。
