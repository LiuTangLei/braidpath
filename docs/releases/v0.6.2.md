# BraidPath v0.6.2

## 改进

- 将 TCP 代理入口、主机和会话的准入上限统一为 512 条活动流。TCP 仍受共享缓冲预算约束。
- 并发较高时合并已有大量数据的 TCP 流确认包，减少返回方向的确认流量。开流探测、FIN 和接收窗口更新仍及时确认。
- 聚合发送端确认降速已生效且丢包几乎未变后，清除旧的拥塞速率阈值。后续探测仍受当前限额和丢包反馈约束。

## 升级

建议服务端和客户端一并升级，以使用两端的新版并发限额。大批短连接与持续下载共用发送带宽，混合负载下的完成时间随路径状态和排队而变。

安装包覆盖 Linux、macOS、Windows、FreeBSD 共 11 个平台目标，包含安装脚本和 SHA-256 校验文件。

## Changes

- Raise TCP admission to 512 active streams at the proxy listener, host, and session. Shared TCP buffer budgets still apply.
- Coalesce ACKs for established bulk streams under concurrent load while preserving immediate feedback for open probes, FINs, and receive-window updates.
- Clear the old overrun threshold when a binding rate cut leaves loss nearly unchanged. Subsequent probes remain subject to the current cap and loss feedback.

Upgrade servers and clients together to use the increased limit on both ends. Completion times under mixed bulk and short-connection load vary with path conditions and queuing.

See [installation and upgrades](https://github.com/LiuTangLei/braidpath/blob/v0.6.2/docs/install.md) and [performance validation limits](https://github.com/LiuTangLei/braidpath/blob/v0.6.2/docs/release-readiness.md).
