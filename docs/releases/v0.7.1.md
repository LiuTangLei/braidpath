# BraidPath 0.7.1

- **Mixed TCP and Game UDP.** `proxy-client --game-mode on` carries bulk TCP responses on native HTTP/3 streams and Game UDP as prioritized DATAGRAMs in the same per-exit session. The low-level clients select the mixed policy with `--game-mode --native-return-stream` and a TCP-capable listener.
- **Native receive backpressure.** Native TCP records wait for temporary receive credit, including reorder slots. Path readers have separate staging limits, and the DATAGRAM lane continues while native reads wait.
- **Shared application budget and interactive responsiveness.** The sender meters native writes in bounded parts alongside Game traffic under per-path native pacing and the existing directional and group ceilings. These ceilings account for application admission; QUIC retransmissions are measured at the transport. Interactive short TCP responses bypass a queued bulk native record onto the DATAGRAM lane without waiting behind bulk downloads.
- **Ordinary native download scheduling.** Standalone `--native-return-stream` dynamically adjusts per-path send storage within 2–4 MiB against congestion window and queue feedback, bounds write-ahead on a much slower route under parallel downloads, and orders paths by estimated backlog completion when three or more paths cooperate on a single download.
- **Optional ordered SOCKS5 UDP.** `proxy-client --ordered-udp-port PORT` (repeatable; ordinary `--game-mode off` only, rejected with `--game-mode on`) carries SOCKS5 UDP for matching destination ports over per-destination reliable aggregate streams to avoid cross-path UDP reordering. It supports IPv4, IPv6, and domain destinations (preferring IPv4 on dual-stack resolution), falls back gracefully if the OS receive buffer ceiling is below 2 MiB, and reopens routes cleanly after peer closure.
- **Game client latency.** The mux submits a bounded burst of Game UDP ahead of TCP work. The sender releases the path membership lock before scheduling, and a busy TCP size refresh can wait for a later turn. Standalone Game defaults to 10 Mbit/s. Mixed Game and native TCP retain automatic pacing by default. A [dedicated macOS Game LaunchAgent](../install.md#macos-game-launchagent) can use interactive scheduling.
- **Game telemetry.** Path snapshots report Game DATAGRAM admission, accepted native payload and DATAGRAM wait before packet selection. The 10 ms Game deadline covers local admission through the Quinn API.

## Upgrade

Upgrade exit/mesh servers first, then aggregate clients (`proxy-client`, `mesh-client`, `client`). Pure relays forward existing reliable streams unchanged. The 0.7.1 aggregate handshake requires the versioned `braidpath-policy` field, carrying a single policy for first admission, additional paths and rejoin. Existing identity files can be reused.

## 中文说明

- 统一客户端用 `--game-mode on` 在同一出口和会话承载 native TCP 下载与 Game UDP；底层客户端通过 `--game-mode --native-return-stream` 组合启用。10 ms 为本地 UDP 准入期限。
- 普通 native 下载支持按路径动态窗口（2–4 MiB）、多连接下慢路预写收束与三路及以上单连接按积压选路；混合模式下每路独立节拍控制并保障短请求回包不被大流量原生记录阻塞。
- 统一客户端普通模式（`--game-mode off`）新增可选 `--ordered-udp-port PORT`（不可与 `--game-mode on` 联用），将指定目标端口的 SOCKS5 UDP 经有序聚合流承载，避免多路乱序。
- 独立 Game 默认限速 10 Mbps，混合 Game 与 native TCP 默认使用自适应速率。macOS 独立 Game 服务可配置交互任务调度。
- 升级顺序为先升级服务端/出口节点、再升级客户端；纯中继可保持现有可靠流转发。聚合握手统一使用带版本的 `braidpath-policy` 字段，现有身份文件可直接沿用。
