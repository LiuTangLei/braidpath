# BraidPath v0.7.0-rc.1

**Status: unpublished integration candidate.** This source prepares the 0.7.0
release; it does not announce a completed release or deployment. Validation of
the combined source remains subject to [release readiness](../release-readiness.md).

## Changes

### Native TCP download return

- Offer `--native-return-stream` for negotiated HTTP/3 response bodies carrying
  bulk TCP download DATA/FIN. Uploads, stream acknowledgments, resets and UDP
  retain their DATAGRAM carrier.
- Keep native packet-loss recovery with a reachable QUIC carrier. Return retained
  stream offsets to recovery when that carrier fails or loses ACK progress.
- Preserve bounded sender storage, receive credit and admission queues. Continue
  consuming DATAGRAMs while native receive admission waits, and arbitrate reads
  between response chunks.
- Prefer suitable low-delay, exercised healthy paths for native-return UDP
  fragments without changing bulk coding or adding copies.

### Game UDP policy

- Separate UDP work from TCP completions and service control, original fragments,
  protection copies and ordinary data in that order at the writer.
- Preserve the original local deadline through queueing and the Quinn connection
  lock. Three UDP copies become eligible at distinct original-ingress ages;
  actual sends still depend on credit, readiness and remaining lifetime.
- Use stream recovery for bulk TCP without proactive bulk parity. Qualify Game
  startup growth using matching receiver-delivery intervals.
- Register numbered Game frames discarded before Quinn accepts them by path
  generation. Remove those local events from finalized network-loss populations
  used by rate control, path selection and FEC; genuine network losses remain.

## Removed interfaces

- Remove the former `--legacy-recovery` mode and its compatibility switches
  `--rtt-source-baselines`, `--random-loss-service` and `--queue-gated-loss`.
  The current source-specific RTT, queue-gated loss and bounded recovery behavior
  is the sole implementation.
- Remove the ineffective `--experimental-socks5-early-reply` alias. Default
  SOCKS CONNECT pipelining and the explicit `--socks5-wait-for-connect` behavior
  remain.
- Remove BQ1C feedback encoding and decoding. BQ2C is the supported quality
  feedback format; the BQ3C capacity-probe container remains supported.
- Remove the offline transfer parser for superseded independent transport logs.
  Structured transfer snapshots remain the supported evidence input.

Remove retired arguments from service definitions and upgrade clients and
servers together. Retired behavior is not retained behind hidden compatibility
flags. Existing identity keys are not replaced by this code cleanup.

## Defaults and limits

Native return and Game are mutually exclusive policies. Use separate sessions
or listeners; the combined flag configuration is rejected. Ordinary forwarding
defaults are unchanged. Operator rate and group ceilings remain active. Automatic Game
rates can affect short uploads, and acceptance must include that workload.
A local UDP deadline is not an Internet RTT guarantee. A receiver's complete
message delivery, transport admission and writer handoff are separate events.

Precursor correctness checks and local model results do not establish acceptance
of this combined candidate. The final source must pass the existing CI and
11-target artifact workflow, plus the selected-policy acceptance recorded in
the release checklist. Measurements and host-specific setup remain private.

## 中文说明

本版本是 **0.7.0-rc.1 未发布整合候选**，用于完成原生下载回程、游戏 UDP
策略及历史实现清理的统一验收，不代表正式发布或部署。

- 下载回程使用可协商的原生 HTTP/3 可靠流，保留字节预算与有界队列；接收准入
  等待期间继续处理 DATAGRAM，原生丢包恢复由对应 QUIC 承载负责。
- 游戏策略包含 UDP 优先服务、错开副本、检查至 Quinn 准入的原始本地期限，
  并将 Quinn 接受前的本地丢弃从网络丢失反馈中分开。
- 删除退役恢复模式、无效早回包别名、BQ1C 旧反馈兼容和旧日志解析入口；
  升级时移除服务配置中的旧参数，客户端与服务端一并升级。
- 原生下载回程与 Game 互斥，须分别使用会话或监听；普通转发默认值保持不变。
  Game 自动额度的短上传表现、混合流量延迟及统一
  源码的跨平台检查仍需完成验收。历史失败记录和真实运行数据继续保留。
