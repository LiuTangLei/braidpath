# Runtime statistics

Client, server and relay accept `--stats-file PATH` for final JSON, `--stats-jsonl PATH` for optional cumulative periodic JSON lines, and `--stats-interval-ms N` (default 1,000; bounds 10–60,000). Create the output directory first; keep private topology and run records under ignored `local/`.

For example, append these flags to a runtime command:

```sh
--stats-file local/run/client.json \
--stats-jsonl local/run/client.jsonl --stats-interval-ms 250
```

Orderly Ctrl-C/SIGINT shutdown and ordinary command errors emit a final snapshot. SIGKILL, process crashes and filesystem failures cannot guarantee a final file. Periodic output is flushed at each snapshot; readers must ignore an incomplete last line. Files are replaced on each invocation, and final JSON and JSONL must have distinct paths.

## Schema and readiness

Schema version 1 contains `role`, `process_id`, a random process-stable `instance_id`, `sample_unix_ms`, `elapsed_ms`, `final`, `outcome` (`running`, `stopped`, `error`), `error`, `bounds`, and `stats`. Samples are cumulative; use counter differences over a selected interval. `elapsed_ms` uses a monotonic local clock. Samples from separate machines are not clock-synchronized.

`stats.ready`, `listener_bound`, `target_configured` and integer `configured_paths` support readiness without parsing logs. A client reports its requested interface/entrance pair count; server and relay report zero. Starting and readiness changes trigger immediate JSONL snapshots in addition to periodic snapshots. For a relay, ready means its front socket is bound and its fixed target is configured; it does not establish target reachability. Each entry of `stats.paths` is keyed by `session_id/path_id`, includes `authenticated`, `request_stream_id`, `sending_direction`, and `quinn.closed`; the latter identifies a closed connection. An adaptive client becomes ready after its first usable authenticated path; simple profiles wait for all initial attempts to finish. Check the expected unique path IDs, a common session ID and the current process instance before beginning a multi-path run.

`stats.shutdown_complete` and `drain_incomplete` describe application task/queue cleanup, not delivery of all packets already submitted to Quinn. Remaining owned input/event/symbol queues are counted as shutdown drops. If cleanup times out, `drain_incomplete` is true and complete conservation assertions must be refused. Even an orderly stop can discard Quinn/kernel/network in-flight packets; these cannot be classified as application queue drops.

## Connection and admission diagnostics

Each path records the current `peer_socket`. Clients additionally record
`local_socket`, including the actual bound UDP port. A wildcard bind does not
identify the egress IP; confirm that independently when needed. On the server,
the peer socket exposes a relay's upstream mapping rather than the original
client socket. Retain both endpoints when comparing repeated five-tuples.

`stats.connection_events` retains the latest 128 events in chronological order. `omitted_connection_events` counts evicted events; `bounds.connection_events` declares the limit. A local `connection_id` correlates stages within a process. Events contain `remote`, optional `path_id`, `phase`, `stage`, `outcome`, a controlled `error` reason code, and monotonic milliseconds: `elapsed_ms` for the current stage, `total_elapsed_ms` for the connection, and `process_elapsed_ms` for the event's position in the run. They contain no authorization headers, bearer tokens, session IDs or arbitrary peer close text. Events trigger JSONL output; retained histories appear again in subsequent cumulative snapshots, so do not count the same event twice.

Server stages identify `incoming` QUIC negotiation (5 seconds), `http3_setup` (no new timeout), `request_resolve` (5 seconds), `peer_settings` (5 seconds), and `admission_wait` (the existing 60-second admission deadline). Client stages identify `quic_connect`, datagram-capacity checking, HTTP/3 setup, peer SETTINGS and authenticated admission, all inside the unchanged 8-second whole-path limit. `timeout_ms` and `timeout_scope` distinguish a stage timeout from the whole-path/admission budget; a null timeout means no additional stage timer. Human diagnostics include remote/path, phase/stage and elapsed times. These fields locate the failed operation; they do not prove a firewall, relay, host or network cause.

`handshake_attempts`, `handshake_successes`, `handshake_failures` and `handshake_cancelled` now count **QUIC negotiation**, rather than the former client's whole authenticated-path attempt. HTTP/3 setup and authentication can still fail after QUIC success. `path_admission_attempts`, `path_admission_successes`, `path_admission_failures` and `path_admission_cancelled` separately count authenticated session POST attempts; public website GETs do not increment them. A rejected attempt remains counted if a later attempt succeeds. `established/connected` closure events cannot increment handshake failures. Local shutdown is recorded as cancellation, and a code-0 established peer close is normal. A connection that closes before completing admission does not become an admitted path. Abrupt task cancellation or process death may leave an attempt unresolved; events and counters do not claim full conservation when shutdown is incomplete.

`bench/readiness.py` consumes schema-v1 snapshots and live process information without parsing logs. It rejects stale process/attempt identities, requires all expected unique active authenticated paths in one client session, and checks server paths against that client session. Its single monotonic deadline includes polling time; callers must bound their own polling I/O by the supplied remaining time. Readiness failure returns a reason and never starts a workload or retries the attempt.

## Scopes and units

`stats.directions` contains aggregate `client_to_server` and `server_to_client` counters. `stats.sessions[session_id][direction]` contains the same counters for one session plus bounded logical-ID windows. On the client, application ingress is a local UDP receive and UDP target delivery is return traffic handed to that local application's socket. On the server, application ingress is a reply received from its fixed UDP target and UDP delivery is forward traffic handed to that target. Successful UDP sends report kernel acceptance, not remote application receipt.

The direction object's `records` and `symbols` are separate layers:

- Application record ingress, oversized/flow/unavailable drops, event queue admission/rejection, sender input queue admission/rejection, consumed/encoding counts and each queue's shutdown cancellation counts.
- Generated original/repair symbols, skipped repair budget, bounded symbol queue admission/full drops, expiry and shutdown drops, and original/repair admissions to Quinn.
- Received original packets (including duplicates), repair symbol arrivals, uniquely decoded original records, FEC recovery, deduplication, stale/invalid symbol drops and UDP send acceptance/failure.

The sender input queue contains records; the pending queue contains original or repair symbols. On the client there is one ingress/sender input queue, so successful `ingress_queue_enqueued` and `sender_queue_enqueued` describe the same admission. Server target replies first enter the session event queue, then the sender input queue; `ingress_shutdown_dropped` and `input_shutdown_dropped` refer to distinct queues. Received aggregate symbols share a bounded event queue and `receiver_queue_*` counters count symbols rather than logical records. Full and closed queue rejections are reported separately. The outgoing scheduler additionally caps each flow at 64 pending originals and the shared repair queue at 64 symbols, within the 256-symbol total; these admission rejections use the symbol queue-full counters. Per-flow service occurs after the common UDP/input queue, so it does not establish kernel-level priority isolation.

`expiry_wait` and `admitted_wait` contain count, total/max milliseconds and a nine-bucket histogram with upper bounds `[1, 5, 10, 25, 50, 100, 250, 1000, infinity]` ms. Each original's waiting time begins at its own application receive, including input-queue and encoder processing. A repair inherits the oldest original ingress time in its block, so encoder waiting does not extend its usefulness. Expiry uses these same timestamps. Adaptive mode uses the smaller of `queue-ms` and `latency-target-ms` for sender-owned waiting; simple profiles use `queue-ms`. `originals_ingress_expired_dropped` counts records expired before encoding, separately from `originals_expired_dropped` for generated pending symbols; both contribute to `expiry_wait`. These local sender bounds do not recall packets already admitted to Quinn or establish an absolute cross-host one-way deadline.

`stats.paths` records original/repair Quinn admission, buffer-full and send-error **attempts**, received HTTP datagrams, receiver queue rejection, decoder outcomes and UDP target acceptance/failure. Recovery is attributed to the path whose arrival triggered recovery, not the unknown path of the missing original. Pre-path application/input/pending queues have aggregate scope: no fabricated path assignment is made before scheduling.

Each path's `quinn` contains cumulative `lost_packets`, `congestion_events`, `sent_packets`, UDP transmit/receive datagram and byte counts, HTTP DATAGRAM frame counts, latest minimum/smoothed RTT, congestion window and closed status. Sending congestion/loss applies to `sending_direction`; UDP receive counts apply to the reverse direction. Initial RTT values can be estimates before enough acknowledgments exist. One QUIC packet can contain several frames, and a UDP datagram can bundle QUIC packets. Control/ACK/handshake traffic is included in QUIC/UDP counts. **QUIC lost packets, HTTP datagram symbols and logical record loss are not interchangeable.**

Quinn also exposes cumulative `ack_frames_tx/rx`, `ack_frequency_frames_tx/rx` and `immediate_ack_frames_tx/rx`. These are frame counts, not ACK-byte totals or physical-interface bandwidth. They support diagnosing reverse traffic without changing ACK behavior. Use independently measured interface/capture evidence when physical uplink consumption matters.

`send_buffer_full_attempts` counts an unsuccessful path capacity check. The aggregate symbol remains queued for retry or later expiry; an attempt is not an additional drop. These counters measure pressure without changing the existing sender admission policy.

Relay direction counters use UDP datagrams, with received/queued/forwarded counts and bytes. Drop reasons distinguish unauthorized source, oversize, deterministic impairment, rate budget, mapping limits/errors/closed queues, queue capacity, socket send errors/cancellation, expired mapping queues and shutdown. `--drop-every` impairs forward ciphertext datagrams only, including handshake/control packets; a counter cannot identify their encrypted record contents.

## Bounded logical reconciliation

Each session/direction optionally exposes `generated_record_ids`, `quinn_admitted_record_ids`, `locally_dropped_original_ids` and `udp_delivered_record_ids`. Each contains `highest_id`, `floor_id` and `recent`; IDs below its floor have been retired. At most 8,192 IDs are retained in each window. These windows are absent from aggregate direction totals because IDs restart at each session. Statistics retain at most 128 session scopes and 128 current logical-path scopes; omitted scopes are counted explicitly. Rejoins replace the current connection reference instead of consuming a lifetime connection slot. Each path keeps at most three scalar previous-generation snapshots, with `total_generations` and `retired_generations` counters. Retired sessions release all live connection references; at most eight recent retired sessions remain, and their historical scopes can be evicted to admit a new active epoch. `retired_session_total`, `evicted_session_scopes` and `evicted_path_scopes` expose pruning. Aggregate direction totals survive history pruning. Complete per-session/path assertions must be refused if scopes were omitted or the compared ID range falls below any relevant window floor. Production-long sessions require interval/window reconciliation rather than a whole-session ID claim.

After a fixed observation/drain period, FEC0 can reconcile admitted original IDs with delivered IDs and explicitly named `not_received_after_drain` IDs. This last set is observed non-delivery, **not an identified cause or a locally recorded queue drop**; it can include external loss, peer rejection and transport/kernel in-flight data. FEC can recover a record whose original symbol was locally dropped before Quinn admission; therefore with FEC enabled, reconcile generated IDs and recovered delivery too, and do not assume delivered IDs are a subset of original Quinn admissions. Local original-symbol drop IDs can overlap records delivered through FEC.

Useful independent invariants after completed application cleanup include:

```text
originals_generated = originals_enqueued + originals_queue_full_dropped
repairs_generated = repairs_enqueued + repairs_queue_full_dropped
originals_enqueued = originals_quinn_admitted + originals_expired_dropped + originals_shutdown_dropped
repairs_enqueued = repairs_quinn_admitted + repairs_expired_dropped + repairs_shutdown_dropped + repairs_budget_skipped
sender_queue_enqueued = sender_input_consumed + input_shutdown_dropped
relay.received = relay.forwarded + classified_relay_drops
```

During a run, add the still-queued/in-flight amount at each layer; periodic snapshots are not a transaction across all layer updates. Repair-budget decisions occur after queue admission, when a block has no pending originals; a skip is therefore a terminal outcome of an enqueued repair. Application conservation additionally includes pre-queue rejection, `originals_ingress_expired_dropped` and encoding failure. Logical records and repair symbols must not be added together. Captures, raw sequence probes and paired endpoint snapshots are required to locate external loss and queue growth.

`tests/stats.rs` exercises exact raw UDP sequence loss under relay impairment, real HTTP/3/FEC0 queue expiry and layered/ID reconciliation, immediate JSON readiness, graceful cleanup, and ordinary-error final JSON. Run records are temporary or local; they are not performance evidence for a remote route. Opt-in receiver feedback is covered by deterministic gap/reorder/tail/replay/clock-offset tests and an authenticated three-path bidirectional integration test. Opt-in path rejoin additionally verifies a changed UDP source port, authenticated fresh-generation feedback and survival of old-handler cleanup.

With `--receiver-feedback`, each path has a `receiver_feedback` snapshot: generation, locally admitted `sent_symbols`/`sent_bytes`, finalized local `received` counters, remote `sender_estimate`, duplicates/late arrivals, and control counts. `sent_bytes` and `received_bytes` count unique measured inner BraidPath symbol bytes, including FEC symbols but excluding the measurement envelope, HTTP mapping and outer transport. V2 feedback carries the receiver's local report time; `delivered_bps` uses consecutive receiver-local intervals, not delayed/compressed control-arrival spacing. It is observed symbol delivery rate, not application goodput or proven capacity. Sequences count original **and repair symbols** before FEC/application delivery. Finalized gaps are not credited by recovery or late arrivals. A 512-symbol window and 500 ms watermark grace bound state; an unusually large sequence jump can finalize older slots immediately. Sender loss is a 0.25 EWMA of interval loss; cumulative `expected/received/lost` remain available. `delay_variation_ms` is transit delta above the receiver running minimum, smoothed with weight 0.2. It cancels constant clock offsets, but is not absolute one-way latency; clock drift remains a limitation. `updated_us` is local per-generation elapsed time of the last report that finalized new symbols; idle control reports do not make an old quality sample fresh.

Report freshness and path reachability are separate. `sender_estimate.updated_us` can advance when only losses are finalized. `sender_estimate.delivered_updated_us` advances only when the peer confirms additional unique delivery. An alternate healthy path can carry a recent report that a failed path delivered nothing; that report is useful loss evidence, not proof that the failed path is available.

Adaptive mode may add positive-byte reports between the regular 500 ms reports. At least 4,096 unreported unique symbol bytes across the paths and a 100 ms admission interval are required; a report less than 100 ms ahead of the regular deadline is skipped. Extra reports use the same v2 fields and authenticated transport, retaining the last full report's `sent`, `expected`, `received` and `delay_us`, while advancing the report number, cumulative received bytes and receiver-local report time. Thus a byte-only report may update `delivered_bps` and positive reachability with `sample_symbols == 0`; it does not refresh finalized-loss quality. A path without a previous full report supplies one first. The regular watermark cadence and 500 ms finalization grace remain separate from byte-rate measurement. Additional reports share the existing feedback counters, bounded pending frame and admission budgets. A delayed pending extra frame remains pending, so an already overdue full report may follow immediately after it finally succeeds.

`receiver_feedback.sampled_us` records the path's per-generation clock when its quality snapshot was copied. Subtract `sender_estimate.delivered_updated_us` or `probe_updated_us` from this value to calculate positive-evidence age. Do not subtract those generation-local timestamps from top-level process `elapsed_ms`, especially after a reconnect. Periodic output still limits the precision with which an admission or state transition can be located between snapshots.

Feedback version 2 is explicitly negotiated; a peer offering only version 1 fails admission rather than silently losing measurement semantics. Every 500 ms a bounded control datagram carries reports/watermarks for all active paths over an authenticated session path. A pending frame remains until Quinn accepts it and consumes the same aggregate/group pacers and Quinn queue budget, with no reliable retransmission after admission. Pending feedback reserves space in the aggregate pacer and one usable path's group pacer before business packets or probes can spend that allowance; other groups can continue serving traffic. Adaptive mode prefers a route with a fresh probe response. Reports cannot cross generations, replay, regress, or exceed locally admitted symbol counts/bytes. `feedback_deferred` counts unsuccessful scheduling attempts, not losses; `feedback_admitted` counts successful admissions. Loss with zero finalized samples or stale feedback is unavailable for decision making. Receiver feedback alone is off by default and leaves original/repair round robin unchanged; its added 28-byte envelope and control traffic require a separate matched baseline.

With source-port rotation or automatic recovery enabled, logical path counters remain cumulative. `reconnect_attempts/successes/failures` describe connection attempts, including initial admissions where a scope already exists; connection events retain attempts that precede path registration. `rotation_attempts/successes/failures` and up to three `previous_generations` retain the old source/peer sockets, last observed quality snapshot and QUIC counters. Rejoin-attempt logs also record newly bound source sockets before connecting, including failed attempts. `quinn` on the current path describes the current connection; previous QUIC snapshots are scalar observations at replacement or retirement, not retained live connections or complete physical transmission totals after that event. Generation IDs and per-generation sequence counts are never added into a fabricated continuous sequence. Connection references and history remain bounded.

## Adaptive control and successful admission

In adaptive mode each path normally sends a small authenticated probe every 500 ms, including during application idleness or probe-only operation after health evidence becomes stale. After short byte feedback has been observed, an eligible fresh path with business backlog and sufficiently young, low-RTT probe evidence uses a 100 ms request interval during both initial and cautious operation, as qualified below. At most four request nonces and one pending reply per path are retained. Replies must match an admitted nonce, generation and three-second age limit; rejected/replayed replies do not refresh the path. `probes_sent`, `replies_received`, `probe_rtt_ms`, `probe_rtt_latest_ms` and `probe_updated_us` describe this local-clock RTT evidence. The latest RTT sample and reply counter distinguish fresh observations from the diagnostic RTT EWMA. `symbols.probes_admitted` includes requests and replies and uses the same bounded budgets. Faster attempts do not bypass Quinn or the aggregate/group limits.

Each path's `adaptive` decision reports `state`, `eligible`, `pacing_bps`, `weight`, `queue_delay_ms`, `probe_due` and `observed_delivery_bps`. Queue delay is an RTT-excess/transport-pressure estimate, not a direct one-way measurement. Cross-host transit drift alone does not trigger an adaptive congestion response. `pacing_bps` is a controller allowance, while observed delivery remains a separate measurement. Growth requires at least 90% actual use of that allowance, with receiver delivery corroborating the initial search. Decisions use the latest finalized `sample_loss_rate` and `sample_symbols`; repeated old loss EWMAs do not create new congestion events. Ordinary congestion reduces pacing while recent positive path evidence keeps the path eligible. `delivered_updated_us` records local receipt of feedback whose unique delivered bytes advance; a new report containing only finalized losses does not refresh this evidence. Health requires positive delivery evidence or a valid probe reply. Missing fresh evidence causes probe-only operation, and a sufficiently sampled all-loss interval with no recent positive proof can stop business earlier. New positive evidence resumes the retained allowance in the same generation. A new connection generation resets the controller.

Original-only exploration uses `sender_estimate.report_time_us`, the receiver-local endpoint of its cumulative byte report. Missing legacy endpoints cannot qualify trials. When observations skip reports, the service numerator and elapsed receiver interval use the same two cumulative endpoints. Never subtract a receiver-local report time from the sender's local clock. Extra short reports are accumulated to receiver intervals of at least 500 ms before occupying one of the four retained service samples. Qualification still requires at least three such samples covering at least 1.5 seconds; the transition `reports` field counts these retained measurement samples, which may each span multiple reports. Invalid or reordered intermediate endpoints cannot advance the window, and a stale gap clears it.

Adaptive `weight` is the actual byte-scheduler weight, in the range 4..2048. It scales the prior pacing/RTT base weight by 16 and applies `(1 - effective_loss)^4`, bounded to 0.25..1, then rounds and clamps to that integer range. The 16-symbol qualification uses cumulative authenticated finalized counts, unlike the separate 4-second loss history used for pacing. Loss quality can therefore reduce the share of a sparsely used damaged path without treating its low offered rate as a capacity limit. Neutral or expired quality preserves prior relative weights; probes and byte-only reports cannot renew finalized-loss quality. Weight is a relative scheduling share, not observed capacity, throughput or a per-path sampling-frequency guarantee.

`weight_loss_rate`, `weight_loss_age_us` and `weight_loss_report` identify the exact qualified fresh raw EWMA sample. The age includes the age already present at observation plus subsequent local elapsed time. A fresh qualified zero-loss raw sample keeps these fields, but can still be constrained by the separately recorded symbol window. `weight_loss_window_expected` and `weight_loss_window_lost` give the counts in the shortest whole-batch suffix containing at least 16 finalized symbols, or all available window batches if fewer than 16 exist. `weight_loss_effective_rate` is the raw EWMA when that window has fewer than 16 symbols, and otherwise the greater of the raw EWMA and the window loss fraction. `weight_loss_window_oldest_age_us` is the original age plus local elapsed time of the oldest retained batch; it can exceed 3 seconds while the latest accepted batch remains fresh. The window resets before a new valid batch after its previous latest batch's age exceeds 3 seconds, and on generation change.

All seven loss-weight fields are null when no qualified fresh raw sample exists, including during pre-maturity window collection and after raw sample expiry. A fresh effective zero-loss estimate has a multiplier of 1, exposing proven fresh evidence separately from missing evidence. These diagnostic outputs let audits reconstruct the actual weight without substituting a newer feedback sample or presenting historical window loss as a fresh raw EWMA. Periodic snapshots can omit intermediate report batches, so they do not constitute a complete ledger of every window update.

Periodic `adaptive` snapshots additionally expose `reprobe`, `last_control` and `rate_changes`. Reprobe transitions identify qualification, baseline, trial, retained service and abort reasons, with generation, report number, matched receiver interval endpoints, actual admitted bytes and integrated allowance. Rate changes identify old/new pacing values and the associated control evidence. Both event histories retain at most 16 entries, with cumulative totals and eviction counters; repeated snapshots are cumulative and must be deduplicated by generation and event number. Packet admission and scheduling use a lightweight decision without copying these histories.

`last_control` and the control evidence attached to a rate change include `local_rtt_ms` (the valid Quinn estimate), `probe_rtt_ms` (the exact probe input used by the controller), `probe_age_us`, `probe_sample_id`, `selected_rtt_ms` and `rtt_source` (`quinn`, `probe` or `unavailable`). An exact numeric tie is labelled Quinn diagnostically; this does not change the original selected value. `mixed_min_rtt_ms` is the shared minimum actually used by the current algorithm, and `rtt_excess_ms` is its actual resulting RTT pressure after the existing freshness check. `transport_wait_ms` is the independent buffer contribution; their maximum is `queue_delay_ms`. The existing `rtt_fresh`, `probe_fresh`, `delivery_fresh`, `new_rtt`, `new_probe` and `new_queue` values expose the evidence available for that observation. `rtt_fresh` copies the original combined freshness (`probe_fresh || delivery_fresh`); it does not independently timestamp a Quinn RTT sample. The event's `at_us` and `control.at_us` retain their separate time boundaries: an off-cycle timeout or refill-driven rollback may attach the previous control observation. Probe ages and freshness flags describe that observation, not a newly sampled RTT at the later action.

The 100 ms probe exception additionally requires an eligible, nonstale path with probe RTT and current response age each at most 200 ms. Age includes elapsed time since `last_control.at_us`. Other paths retain 500 ms attempts so long replies are not systematically evicted from the four admitted-nonce slots by a faster schedule.

In short-feedback mode, `service_symbol_delivery_bps` and `service_sample_span_us` identify the latest qualified service interval used for capacity memory, draining and service corroboration. They use matching cumulative receiver endpoints over at least 500 ms and are omitted before a sample qualifies, after expiry, and for legacy cadence. `latest_symbol_delivery_bps` remains the latest raw interval and can still fund initial receiver-keeps-up evidence. Ordinary initial and recovery growth in this mode requires a new probe received within 200 ms and begun after the previous increase; a new reply number alone does not prove that timing. Initial growth, known-service and cautious recovery, and drain restoration consume the same probe credit. Their multiplicative increment is capped by both the prior limit and `1 + min(0.5, max(0, 0.8 * target_ms - queue_delay_ms) / probe_rtt_ms)`; even an old higher drain hint cannot bypass that single-step limit. This subtracts current queue from the incremental queue-work heuristic and does not establish a hard latency bound. The independent, separately qualified `ReprobeStart` grant retains its own finite trial rules.

Optional `service_admission` records a valid paired local admission interval alongside the receiver service interval: actual `symbol_bytes`, `symbols`, `symbol_bps`, local `span_us` and `started_us`, `backlog_since_us`, `last_pace_change_us`, and `deficit`. The successful cumulative inputs come from the current Quality snapshot, including admissions before the controller's first observation. The two rate denominators use their own clocks; no absolute cross-clock subtraction is performed, and they need not cover the same in-flight symbols. Missing/decreasing sender coordinates or a stale gap invalidate pairing without replacing the receiver-only service estimate. Older traffic may legitimately drain faster than new local admissions.

`deficit` is true only on a new completed service window, with at least 500 ms of local admissions and eight successful symbols, observed backlog throughout that interval, its start at or after every recorded pace change, and no current-observation trial rollback. Receiver symbol service must be below 85% of actual admitted symbol rate, and wire-adjusted service below 85% of current pace. This independently permits a `delivery_shortfall_brake`, even with a low old probe RTT or less than 90% allowance use. A real reduction marks caution and replaces an old drain hint; zero service retains the bounded 0.8 fallback and minimum pace. It does not modify finalized-loss tests, loss overrides, scheduling weights, memory update rules or growth credits. The evidence and desired target remain approximations because report phases differ and the wire conversion uses the shorter control-round mix.

`service_discovery` rate changes use the same ordinary probe and RTT limits while retaining cautious history. A qualified service endpoint must be newly observed since the last increase and locally at most 200 ms old; current positive delivery must also be at most 200 ms old. The endpoint's local observation time is private controller state, not a cross-clock subtraction or a claim that its entire receiver interval follows the last growth. With queue at most one quarter of the target, no ordinary loss, and service supporting at least 85% of exercised allowance, one step may use the existing 25% recovery limit instead of the slower cautious search. Reusing a completed interval cannot fund another discovery, including when it arrived between control ticks. Startup probe excess between half and one full target still stops growth, but follows the normal 100 ms persistence rule before braking; a new rising probe at or above the target can brake immediately.

`startup_probe_excess_ms`, when present, records raw-probe pressure relative to a separate per-generation probe minimum in the fast initial phase or its continuing queue episode. `queue_delay_ms` is the maximum of this value, the existing `rtt_excess_ms` and `transport_wait_ms`. This can expose a queue while the selected Quinn estimate remains low. The original selector and its source-switching limits remain; this additional minimum cannot identify a queue already present at startup. A new rising startup probe at or above the full target can trigger the existing bounded brake immediately; sub-target pressure needs the normal 100 ms persistence. Confirmed pressure survives the phase change until a new young probe observes the existing clear range or the original observation becomes older than 3 seconds; unchanged evidence does not refresh its age.

In short-feedback mode, a moderate probe-derived queue below four targets keeps growth paused but cannot independently repeat a brake when the probe request began at or before the previous actual brake. Request timing is inferred from local reply age and the measured round trip. Missing timing, selected Quinn pressure, a rising raw Quinn estimate, transport wait and severe queue retain the conservative queue-brake path. A post-brake probe can authorize another brake. Exercise for the pressure episode is captured at its first actual reduction; entering short-feedback mode discards a provisional legacy flag only if that episode never actually braked.

`fast_loss` retains the raw new finalized-batch test used for health, growth hold and trial safety. Optional `brake_loss` records the separate evidence for repeating a fast pace brake: the authoritative current-generation `admitted_symbols`, `previous_brake_symbols`, provable `expected` and `lost` counts after that boundary, `pressure_override`, and `actionable`. Every symbol before the brake boundary may explain one lost symbol in a straddling batch, so only the remaining loss lower bound can be attributed to later admissions. Fewer than eight provable new symbols or less than 50% provable new loss does not independently brake again; this is insufficient attribution, not a claim of loss-free new traffic. Severe queue, blocked transport or exercised settled underdelivery preserve the original raw fast-loss safety rule through `pressure_override`. Missing or invalid sequence coordinates retain the original rule and omit this optional diagnostic. The boundary comes directly from the current Quality State on an actual congestion reduction, includes successfully admitted repair symbols, and resets with the generation; a pure trial-credit rollback does not consume it. All raw loss statistics and scheduling weights remain intact.

`observed_local_min_rtt_ms` and `observed_probe_min_rtt_ms` are additional diagnostic minima within the generation, updated only from eligible fresh observations. They are never read by control or weighting decisions and are not calibrated or trusted baselines. They cannot prove a queue-free path, complete sampling of every RTT, or absolute one-way latency. In particular, the current mixed-baseline source-switching defect remains visible rather than fixed. All these fields are bounded scalars; the surrounding 16-entry event history still has cumulative eviction counters, so it is not a complete packet trace.

The controller retains previously achieved delivery to guide bounded recovery trials. Its minimum RTT is per generation and currently has no aging mechanism: a permanent propagation change can remain classified as excess delay, and a permanent capacity reduction can still motivate bounded upward trials. These are explicit long-run validation limits. Sender admission uses only local ingress age for expiry; the RTT-excess estimate affects pacing and does not extend or get added to that local deadline.

`originals_quinn_admitted_bytes` and `repairs_quinn_admitted_bytes` count complete HTTP datagrams accepted by Quinn, including the measurement envelope when enabled. Scheduler service and repair credit settle only on this successful event. Repair credit is a percentage of admitted original bytes, capped at 2,400 repair bytes, and spent on admitted repair bytes. Generated or expired originals create no credit. The outer pacers add an 80-byte transport estimate, so these counters do not equal exact NIC bytes; QUIC ACKs, handshakes and retransmissions require the outer counters. `repair_no_diverse_path` records a timely fallback to a path that admitted originals of that block; logical path diversity does not prove physical independence.
