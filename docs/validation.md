# 验证方法

测试代码用于持续验证行为；测试记录、运行结果和历史实验总结仅保留在本地，不提交到本仓库。

## 网络版本必须覆盖的矩阵

| 维度 | 场景 |
| --- | --- |
| 拓扑 | 1×1、1×3、2×1、2×3；直连与中继同时存在 |
| 方向 | 上传、下载、双向并发 |
| 丢包 | 0%、1%、3%、5%、10%；独立随机与突发丢包 |
| 相关性 | 独立路径、共享最后一公里、共享回程瓶颈 |
| 时延 | 相近 RTT、明显不对称 RTT、变化抖动、乱序与重复 |
| 容量 | 相同 / 不同带宽、单路径断流与恢复、主服务器限速 |
| 负载 | 稀疏交互、小请求、持续大流、短流与大流共存 |
| 网络 | IPv4 / IPv6、NAT 闲置、MTU 变化、接口切换 |

每组比较最佳单路径、无主动冗余的多路径、FEC 多路径；有实现后加入受预算副本方案。基线使用相同加密、MTU、拥塞约束和总链路条件，记录 FEC 占用后的有效业务吞吐。

先用固定随机种子和显式时钟的模拟验证恢复，再做 loopback / 可控损伤网络，最后做真实双向网络实验。模拟结果与公网结果分开存放。

## 报告规则

- 一行记录一个完整试验：提交、配置、随机种子、方向、持续时间、样本数和环境。
- 同时报告 P50/P95/P99、goodput、完成 / 超时 / 失败数量、wire 开销、CPU 和内存。
- 延迟说明是 RTT、单向交付还是请求完成时间；单向值须说明时钟同步方法。
- 超时样本保留。成功样本分位数明确标注为有条件结果，不用 RTT max 代替 P99。
- FEC 的收益必须在相同总资源约束下比较，避免把多花带宽当作免费收益。
- 局部修复率不能替代业务完整性；双向传输应核对字节数与内容摘要。
- 测试记录、运行结果、原始抓包和基础设施明细留在忽略的本地目录，不随源码提交。

任何百分比收益都必须有上述数据支撑。
