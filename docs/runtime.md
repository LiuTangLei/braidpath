# Experimental runtime

BraidPath forwards unreliable UDP messages to one operator-configured destination and, optionally, TCP connections to one operator-configured TCP destination as [reliable streams](reliable-streams.md). An optional SOCKS5 CONNECT / HTTP CONNECT entrance carries TCP connections to client-named public destinations on the same streams. Each path uses real HTTP/3 over Quinn/rustls, with authenticated HTTP Datagrams. The same entrance carries SOCKS5 UDP ASSOCIATE datagrams as unreliable records. There is no Xray runtime, TUN device or transparent IP tunnel.

## Local quick start

Build with `cargo build --release --locked` (Rust 1.88+). The following commands run from the repository root. Keep the long-running commands in separate terminals.

```bash
# Run once. Refuses to replace an existing identity directory.
./target/release/braidpath init --dir local/identity --name localhost

# Terminal 1: test destination (or use your own UDP service).
./target/release/braidpath echo --listen 127.0.0.1:9000

# Terminal 2: main server.
./target/release/braidpath server --listen 127.0.0.1:7443 \
  --cert local/identity/cert.pem --key local/identity/key.pem \
  --token-file local/identity/token --target 127.0.0.1:9000

# Terminal 3: client. Applications send UDP to this local port.
./target/release/braidpath client --listen 127.0.0.1:7000 \
  --entrance 127.0.0.1:7443 --server-name localhost \
  --ca local/identity/cert.pem --token-file local/identity/token

# Terminal 4: ordinary HTTP/3 and end-to-end datagram checks.
./target/release/braidpath get --entrance 127.0.0.1:7443 \
  --server-name localhost --ca local/identity/cert.pem
./target/release/braidpath probe --target 127.0.0.1:7000 \
  --count 1000 --size 1000 --pps 200 --deadline-ms 250
```

For separate hosts, bind the server to its intended address, use a certificate matching `--server-name`, and securely copy the public certificate and token to the client. Keep the private key only on the main server. `init` creates a self-signed test certificate; production identity provisioning and rotation are not automated. One server token defines one authorization domain. Unix identity permissions are restricted; operators must restrict credential ACLs on Windows.

The local client listener should stay on loopback unless other local-network callers are deliberately authorized. Its callers share the tunnel credential. The main server permits only its configured UDP and TCP targets, and with `--proxy` also globally routable TCP destinations named by the client.

## Multiple entrances and interfaces

A loopback relay can be added in another terminal:

```bash
./target/release/braidpath relay --listen 127.0.0.1:7444 \
  --target 127.0.0.1:7443 --allow-source 127.0.0.1
```

Restart the client with both `--entrance 127.0.0.1:7443` and `--entrance 127.0.0.1:7444`. For remote relays, configure the main server's reachable address and allow the client's actual public source IP. No credentials or TLS keys are installed on relays. Each client socket gets a separate return mapping; relay backhaul traffic goes directly to the main server.

On Linux, repeat `--interface eth0 --interface wlan0` to create the interface–entrance Cartesian product, up to eight connections. Binding requires appropriate socket permissions and routes; it does not create policy routes. Non-Linux explicit interface binding returns an error. Without the option, all platforms use the default route. Creating several connections on one interface does not demonstrate multiple access links.

## Policy and limits

Endpoint and relay UDP sockets request an 8 MiB kernel receive buffer. A bulk
path arrives in paced bursts, and the platform default holds only a few
milliseconds of them; the excess is dropped before the process reads it and
counts as path loss. macOS grants the request. Linux caps it at
`net.core.rmem_max` (often about 208 KiB), so raise that on servers and relays,
for example `sysctl -w net.core.rmem_max=8388608`; the process warns once when
its buffer is limited.

Normal use needs no FEC option: automatic protection is already enabled and can
select zero bulk repair on a clean link. `--fec K` overrides that policy for fixed
coding, older-peer compatibility or controlled diagnostics; `--fec 0` disables it.

| Option or bound | Meaning |
| --- | --- |
| `--fec auto` (default), `--fec K` | [Automatic loss adaptation](automatic-fec.md) from no repair through 4+1; numeric K fixes K+1 (0 disables, maximum K=32) |
| `--block-ms 3` | Maximum encoder block age, driven by a 1 ms timer; originals are emitted immediately |
| `--redundancy-percent 30` | Repair HTTP-datagram byte budget credited only by successfully admitted originals; saved credit is bounded |
| `--small-fec-bytes 0` | Optional immediate single-record XOR repair threshold, at most 1,000 application bytes; requires FEC0/redundancy0 unless mixed mode is explicit |
| `--mixed-fec` | Explicitly combine small-record repair with ordinary FEC for larger records; disabled by default, negotiated by both peers |
| `--congestion bbr` (client/server) | BBR is the only runtime congestion controller; each QUIC connection still controls its own congestion window |
| `--rate-bps auto` (adaptive) / `10000000` (otherwise) | Per-session, per-direction aggregate pacing cap, including an estimated header allowance; independent QUIC congestion control remains active. `auto`, the adaptive default, requires `--adaptive` and sets no operator cap below the validated 1 Gbit/s session maximum; per-path adaptive control then sets the pace. Without `--adaptive` the cap is the sending pace and must be a number |
| `--legacy-recovery` (client/server) | Restore the earlier adaptive recovery: 100 ms queue-brake spacing, post-brake restoration only from the qualified 500 ms service window, 20% cuts for unexercised new-queue brakes, fixed 3% cautious steps, caution that never ends once established, and loss-only brakes at any queue delay; off by default |
| `--adaptive` | Opt-in per-path pacing, sender-age admission, fresh-health eligibility, independent RTT probes and automatic startup/outage recovery |
| `--capacity-probe-bps 0` | Optional independent delivery samples; disabled by default, requires adaptive FEC0, capped at 5% of aggregate and each group budget |
| `--probe-guided-recovery` | Optional bounded recovery using those samples; disabled by default, requires FEC0 and zero redundancy |
| `--latency-target-ms 20` | Local sender-age limit and added-delay control objective; does not bound propagation RTT or end-to-end delivery |
| `--path-group GROUP` | One group ID per interface–entrance pair; omitted assignments default to the interface index |
| `--group-rate-bps GROUP:BITS_PER_SECOND` | Shared per-direction cap for every path in that group; repeat for different groups; each cap is 64,000..aggregate bits/s |
| Server `--max-rate-bps auto` | Caps the session's server-side sender; not a server-wide or inbound traffic policer. The default `auto` accepts the client's request up to the validated 1 Gbit/s maximum; a number keeps an operator cap |
| `--queue-ms 100` | Sender lifetime starts at original application ingress; adaptive mode uses the smaller of this and `--latency-target-ms` |
| Message size | 1,000 application bytes; no fragmentation; larger local UDP messages drop |
| State | 16 sessions, 8 paths/session, 64 flows/session, 256 queued events/records, 256 decode-block slots, 8,192-ID dedup window |
| Sender symbol queue | At most 256 total symbols, 64 originals per flow and 64 repairs; admitted flows receive turns |
| Lifetimes | Receiver repair waiting uses `--queue-ms`; UDP flows expire after 60 s idle; adaptive sessions retain an empty-path epoch for approximately 120 s |
| Relay | Fixed destination, explicit source allowlist, 64 mappings, 32 queued packets/mapping, 30 s idle; shared bidirectional byte-rate cap |

Adaptive recovery retains a measured return target after a qualified queue brake even when the local queue is empty at that exact sample. The existing demand check still applies to the brake. Returning to that target requires current queued demand and a fresh post-brake RTT reply showing that the queue has drained; the target is capped at 90% of the pace before the queue-braking episode, and a lower drain measurement reduces the applied target. The existing freshness, pressure and pacing bounds remain in force.

Queue delay is the selected RTT minus the lowest RTT seen from the same source: Quinn and the authenticated probes each keep their own minimum, so a stable offset between the two estimators is not queue. A queue brake paces below the service it measured, which drains a queue this sender built. If, after two RTTs plus 400 ms, the excess stays at least half the latency target and stable (the minima of two halves of a further `max(2·RTT, 400 ms)` window within 10% of that floor, bounded to 1–5 ms, and the deciding sample within 25% or 5 ms of it) while the pace has not risen, the local queue stayed empty and the transport was not blocked, the excess is treated as a longer path: every queue reference rises by it and the pace returns to 90% of the pace before that brake (`baseline_refresh`). Only samples from traffic delivered after the brake count, and a gap longer than half that window between them restarts the test, so probe replies alone or evidence from before a pause cannot restore the pace. An unstable window, such as one ending on a jitter spike, starts another at once with the same pre-brake pace, at most three per episode. A falling or growing excess, or any pace increase, ends the test. Outside such a test, a pace of at most 1 Mbit/s is eligible for a light-load baseline heuristic while the local queue stays empty and the transport is not blocked. Each fixed `max(4·RTT, 1 s)` window needs at least four samples in each half; a gap longer than half the window restarts it, and a completed underfilled window is discarded. Both half-window minima must agree within 10% of the lower one (bounded to 1–5 ms), the deciding sample must be within 25% of that floor (bounded to 2–5 ms), and the floor must exceed the clear-queue level (5% of the target, at least 2 ms). Only then does every queue reference rise by the floor, without changing the pace. A route that lengthened after its minimum was sampled, or a constant offset just above a quarter of the target, otherwise holds the path below the growth gate at the minimum pace indefinitely and keeps its loss from ever being measured on a clear queue. A lower sample still lowers each reference at once. The absolute bound avoids remembered service that may be stale after a capacity step. A positive delivery shortfall below 85% of actual admissions is a capacity deficit only under sustained demand (continuous backlog, or admissions at 90% of the pace); without it only delivery below half of admissions, including zero, counts. `--legacy-recovery` restores the shared minimum, the permanent reference and the earlier deficit rule.

`--capacity-probe-bps` negotiates fixed 1,000-byte measurement frames in both directions. Its separate allowance charges HTTP-datagram bytes plus the same estimated header cost as other traffic. It has no startup credit, spends only on successful Quinn admission, and also obeys aggregate, group, transport and feedback-reserve limits. Frames have their own sequence, receiver clock, bounded replay window and generation. They never reach the UDP application or count as business symbols, service, health or pacing evidence. Feedback shares the existing pending control record and reserved aggregate/group budget; that control cost is outside the additional probe-data allowance. `capacity_probe` path statistics count the 972-byte measurement body and its observed delivery, which does not establish available capacity. Without `--probe-guided-recovery`, this option measures only and does not change scheduling. A peer that does not negotiate it is rejected.

Probe data starts at at most 64 kbps per path and its share of the configured aggregate/group allowance. When business measurement is unnecessary, the pilot also shares a 64 kbps group ceiling. A fresh, complete paired business interval that covers the exercised allowance can pause probe data while continuous queued demand, fresh positive progress and an unblocked transport remain present. A zero probe-data ceiling cannot spend retained tokens; health requests remain independent. It continues independently of business eligibility. Only continuously queued business demand for at least 500 ms, new positive probe delivery and a new post-change RTT reply permit a bounded increase; the configured 5% share remains an outer ceiling. One RTT reply cannot fund repeated increases. During sustained queued demand, measurement requests RTT without requiring a recent reply, at most once per 100 ms and no faster than half the last measured RTT. Successful request admission spends this opportunity; rejected sends keep it pending. The existing control budgets, feedback reserve and bounded nonce tracking still apply. Idle paths retain the health-check cadence. Added queue above half the latency target with a new reply, or persistent transport blocking, reduces the probe pace. After 500 ms without queued demand it returns to the low pace. New generations have zero initial credit. `capacity_probe_rate` statistics expose the actual budget and its increase/reduction counts.

`--probe-guided-recovery` uses two paired clocks over at least 500 ms, at least 32 actual probe admissions, 16 received probe bodies and 64 finalized probe symbols. It selects the shortest retained interval meeting those count floors, up to the existing 3 s horizon; sparse traffic cannot borrow older cumulative counts. New service must be at most 200 ms old, positive probe progress at most 200 ms old, and finalized probe loss at most 500 ms old. A covered business pace cannot exceed half the lower of the current and previous probe-body service rates. Business loss must match the independent recent loss within one business symbol of count resolution, both over the retained interval and a new interval of eight or more symbols; an entirely lost new interval never qualifies. Raw loss and counters stay visible. With fresh RTT, at most one quarter of the delay target in queue, positive business service and no blocked transport, covered loss/positive underdelivery can pause repeated loss-only braking. Queue, blocked transport, zero service, worse business loss and expired credit retain the original brakes. Growth uses a wholly post-increase local probe-admission interval, a new RTT reply, the existing retry delay and a step capped at 25% and by RTT plus reply spacing. Every such increase owns the existing two-request/two-reply withdrawal monitor. Probe bytes remain outside business statistics and capacity memory; this credit is a heuristic for bounded exploration, not a capacity estimate or delivery guarantee.

The client requests one rate cap for both sending directions. The server uses the smaller of that request and `--max-rate-bps`; increasing the server maximum cannot undo a smaller client request. Group caps are negotiated in the same way. Separate upload and download ceilings are not currently configurable. With the defaults (`--adaptive` client `--rate-bps auto`, server `--max-rate-bps auto`), neither endpoint needs a link-speed estimate: the cap no longer restricts the per-path controllers, which still start low and grow only on measured delivery, queue delay and loss. This is not a fixed-rate sender. Shared-bottleneck `--group-rate-bps` caps remain optional. For an asymmetric measurement, choose a cap that permits the intended download, constrain the upload workload independently, and measure transport ACK/control traffic at the client interface.

Originals are never delayed merely to fill a block. At 200 messages/s, the default 3 ms block often contains only one original: the repair budget can skip many singleton repairs. Use a deliberate larger block deadline (for example 25 ms) when comparing full four-record blocks, and count the additional recovery wait. The existing FEC defaults are unchanged; the adaptive mode does not select a new FEC configuration.

Repair credit is now created only after an original HTTP datagram is accepted by Quinn. Originals dropped before admission, including expired input, do not create credit. Repair credit is spent only on actual repair admission, with a bounded balance; insufficient credit cannot block original service. Repairs prefer an eligible path not used by their block's admitted originals, but this is a best-effort preference. The budget counts admitted HTTP-datagram bytes, not exact NIC wire bytes or confirmed delivery. Aggregate and group pacing also charge feedback, probes and an estimated header allowance. Handshake, ACK, transport retransmission and relay backhaul costs require separate measurement.

Each path has its own writer task that moves datagrams into Quinn. Quinn's connection driver holds the connection lock while it sends UDP, so a single sender calling into every connection would wait for each busy driver in turn, and the paths would effectively send one after another. The sender reads only lock-free connection hints (closure, buffer space, maximum datagram size, RTT, congestion window) published by a small Quinn patch (`vendor/quinn/PATCH.md`). A path holds at most what its pace sends in 1 ms, or one datagram when that is less, in its writer and Quinn's datagram buffer together. `--datagram-send-buffer-bytes` (default 76,800) is only the ceiling of that buffer; 1,200 keeps one datagram per path. The application cannot expire or recall a record after the writer accepts it: this is a byte bound, not an end-to-end deadline guarantee.

When a queued symbol passes the admission gates but its path's local budget is full, the sender also waits for Quinn's drain notification. The symbol stays at its application queue head while waiting. Every poll rechecks its original ingress age, current connection and generation, path eligibility and available credit; only acceptance by the path's writer removes the symbol and commits pacing, scheduling and repair accounting. Any intervening sender event cancels the pending wait before changing the queue. This adds a readiness wakeup for one candidate path while retaining the existing 1 ms timer and bounded buffer; it does not establish a hard real-time delivery guarantee.

The baseline scheduler round-robins open connections whose writer has room for the symbol. The optional quality scheduler preserves its simpler weighted policy; byte service is charged only to the path that actually accepts a symbol. Failed attempts spend no service credit. Adaptive mode additionally checks local ingress age, path-health freshness, per-path pacing and a shared business allowance. A path without enough business allowance for the current symbol does not accrue that symbol's weighted service share; this prevents unsendable large packets from creating service debt that pins later small packets. Readiness is checked again at actual admission, including after waiting on Quinn. Neither mode automatically detects shared bottlenecks or couples congestion windows.

Original expiration uses application ingress time across input and symbol queues. Adaptive mode drops originals after `min(queue-ms, latency-target-ms)` of sender age. Admission checks that local age alone; estimated network queue delay separately affects pacing and scheduling weights. A nonexpired original still needs an eligible path, pacing budget and room in its path's local budget. Repair lifetime begins with the earliest original in its block. At the receiver, `queue-ms` bounds repair waiting; retiring a repair block does not itself invalidate a previously unseen original. These local policies cannot recall an original already in Quinn, a kernel queue or the network, and do not establish an absolute end-to-end deadline guarantee.

The per-flow and repair queue caps prevent one bulk flow and its repairs from filling every sender symbol slot. They do not reserve kernel or ingress-channel capacity for an interactive caller, and do not establish complete end-to-end traffic-class isolation under overload.

Queues and decode windows are bounded, but this is not hostile-load acceptance. The server accepts up to 128 active connections and bounds handshake/request resolution time. Authenticated clients share the server token's resource domain. Process supervision and deployment quotas remain operator responsibilities.

## Wire profile v1

### Mixed small and large record protection

For a mixed workload, explicitly request all three coding parameters and the
mode acknowledgement, for example:

```sh
--mixed-fec --fec 4 --small-fec-bytes 128 --redundancy-percent 30 --block-ms 8
```

This is a selected experimental policy; defaults use automatic FEC, block age 3 ms,
30% ordinary repair, no small threshold and no mixed mode. Mixed mode requires
positive FEC, threshold and ordinary redundancy, and excludes independent
capacity probes. A peer must explicitly acknowledge `braidpath-mixed-fec: 1`.
Legacy ordinary-only and small-only policies preserve their existing encoding.

Small records form independent k=1 blocks and retain immediate original/repair
generation and the small-record path eligibility guard. Larger records enter
their own k-record encoder, so a small request cannot enlarge its repair to the
size of a neighboring bulk record or consume a bulk block position. Both
encoders allocate block IDs from one dense sequence when a real block opens;
the existing envelope and shared 256-block decoder window remain unchanged.
At extreme small-record rates an unfinished bulk block can still fall behind
that bounded receiver window. This mode does not extend the window, silently
extend a deadline, or recover arbitrary multi-record erasures.

The repair accounts are separate. An actually admitted small original grants
at most one already-generated, queued small repair. Its reservation covers
that repair plus negotiated quality framing and the largest legal HTTP stream
mapping; admission consumes the authorization once using actual HTTP bytes.
A rejected or expired original grants no authorization. Larger originals alone
earn `redundancy-percent` credit, and larger repairs debit it only when Quinn
accepts them. Small traffic cannot subsidize large repair. A bulk repair waiting
for insufficient credit cannot hold an eligible small repair behind it.

The configured percentage applies to ordinary large-record repair, not total
redundancy. Each protected small record can add roughly one copy. Even a full
k=4 block has framing differences, and a one- or two-record short block still
needs a full repair symbol. Thus k=4 is not an exact 25% byte-cost promise and a
25% budget need not admit every repair. Select the block wait deliberately and
measure generated, admitted, budget-skipped and expired repairs together with
small request deadlines and large-record delivery after recovery.

Every admitted repair still consumes aggregate/group pacing, available Quinn
space and the existing sender deadline. Original records are emitted promptly;
repair age starts with the oldest original ingress in its block. Repair credit
does not establish physical wire transmission or peer receipt. Those costs and
outcomes require separate observations in both directions.

### Receiver-local adaptive FEC retention

`--adaptive-fec-retention` is an optional **local** client/server flag. Enable it
on each receiving endpoint independently. It does not change negotiation, sender
`--queue-ms`, pacing, repair budgets, coding or original-record delivery. Without
the flag, the existing fixed receiver policy is unchanged.

The controller starts at 100 ms and stays within 50..250 ms, measured from the
first locally received symbol of each block. It follows the largest distinct
symbol arrival span in eight one-second buckets, with 25% plus 5 ms margin.
It increases immediately on new evidence and decreases at most once a second,
by roughly 10% (at least 5 ms), only with at least 32 recently sampled block/epoch
pairs. Quiet periods without evidence do not cause optimistic shortening.

Per-block first timestamps and unique-symbol masks survive payload retirement in
the existing 256-block window. This lets a distinct late symbol teach future
retention without censoring all samples beyond the old limit. Duplicate symbols
cannot train the controller or renew a deadline; observations beyond the 250 ms
hard horizon are ignored. A still-live block may receive more time within that
first-arrival cap. Expired state is never revived, the block-ID window is never
expanded, and a decrease applies only to newly opened blocks.

An idle expiry timer releases decoder payloads without waiting for another packet.
Available originals and successful reconstructions are still emitted immediately;
retention is not an extra playout buffer. The 250 ms local state horizon is **not**
an end-to-end deadline promise, and one XOR repair still cannot recover multiple
missing members. The feature is opt-in until workload-specific validation.

`examples/receiver_retention_replay.rs` accepts a finite explicit corpus of source
IDs, payload lengths, block membership and receiver-local arrivals. It uses the
real codec/receiver with synthetic payloads. A replay can test mechanism and
record-set changes, not network throughput or cross-machine deadline performance.

A client's `--interface` binds each QUIC socket without changing system routing:
Linux accepts the device name; macOS accepts `ifindex:<nonzero index>` (resolve it
with `python3 -c 'import socket; print(socket.if_nametoindex("en0"))'`). macOS reads
back the kernel option and fails if the binding was not retained. Use `--path-bind`
for an explicit local source address. These options do not alter system proxies.

### Envelope and session mapping

- TLS verifies the main server's certificate and name; ALPN is `h3`. A resumed connection sends its session request as 0-RTT data and the server answers at 0.5-RTT, so a path with a ticket is admitted one round trip after its first packet; see [0-RTT](#0-rtt). Both peers must advertise QUIC DATAGRAM capacity and HTTP/3 `H3_DATAGRAM` support.
- `GET /` serves a small ordinary HTML page. Unknown requests and unauthenticated `POST /session` return the same 404 response. This is a functional HTTP/3 endpoint, not browser impersonation or a complete production website.
- A long-lived `POST /session` carries the bearer token and version, random 128-bit session ID, path ID and policy headers. Joining another path requires the same credential and session policy. A request FIN or connection closure removes that path. An adaptive session retains an empty-path epoch for approximately 120 s; a baseline session ends when its last path leaves.
- This is a BraidPath application mapping using RFC 9297 HTTP Datagrams, **not CONNECT-UDP, MASQUE, WebTransport or Xray compatibility**. It has no Capsule or reliable HTTP-body fallback.

#### 0-RTT

| Element | Behavior |
| --- | --- |
| Tickets | The server issues four TLS 1.3 tickets per handshake and keeps up to 4096. Tickets are stateful: rustls accepts early data only for a ticket it holds and removes the ticket on use, so a replayed first flight is completed, if at all, without its early data. |
| Ticket journal | On Unix the server also records tickets in `<key>.tickets` beside its private key (mode 0600; `key.pem` gives `key.tickets`, held with a `key.tickets.lock` lock file), so clients keep resuming with 0-RTT across a server restart. A use is appended and flushed to stable storage before the ticket reaches the handshake, so single use survives a restart or crash; an unflushed issue only costs a full handshake. After a failed write the server refuses every ticket until it restarts, so no record is appended behind a partial one. The journal is bound to the server certificate, drops tickets older than their 24-hour lifetime and is rewritten atomically as it grows. A second process using the same key, a failed open and other platforms keep tickets in memory only, with a warning; a restart then forgets them. Deleting the file revokes every ticket. |
| Client | Every endpoint with the same CA shares one TLS configuration, so a reconnecting path (which binds a new endpoint) uses a ticket from any earlier connection. rustls binds tickets to that verifier and keeps eight per server name, in memory: the client's first connection after its own restart uses a full handshake, because rustls 0.23 cannot export or import client tickets. Every attempt spends a ticket, including attempts that fail during an outage. |
| Admission | The session request is sent without waiting for peer SETTINGS; SETTINGS are checked after the response, before datagrams are used. With a ticket, admission takes one round trip; without one, two. |
| Rejection | If the server refuses early data (a restart without the journal, a spent, expired or evicted ticket), the request never reached it. The client closes that connection and repeats the attempt with a full handshake inside the same 8 s path limit. |
| Server bound | The server serves 0.5-RTT before the handshake completes and closes any connection whose handshake does not complete within 5 s. |
| Statistics | `zero_rtt_accepted` (both roles) and `zero_rtt_rejected` (client only; a server cannot tell a rejection from a client that sent no early data). The full-handshake retry after a rejection counts as a further handshake attempt. |

Early data has no forward secrecy against compromise of the server's ticket state, in memory or in the journal; protect the journal like the private key.
- Each QUIC DATAGRAM contains the request's Quarter Stream ID, context ID zero and one BraidPath record. Variable-width Quarter Stream IDs are encoded and checked; contexts, versions, lengths and bounds are validated.
- BraidPath envelope: `BP`, version byte `1`, kind byte (data `0`, XOR repair `1`, plain `2`), big-endian 64-bit block ID and 8-bit shard index (or source count for repair records). The payload is the codec shard (length-protected XOR bytes for repair), or a plain record. Canonical application records contain a big-endian 32-bit flow ID, 64-bit delivery ID and UDP payload. Maximum encoded envelope: 1,027 bytes.
- Flow/delivery IDs are scoped to the authenticated session and sending direction. Delivery IDs survive FEC reconstruction; late originals and duplicates are suppressed within the bounded window. Expired blocks cannot be reallocated by delayed shards.

BBR is the only runtime controller in this latency- and throughput-focused implementation. Quinn labels its BBR implementation experimental; the choice is not a universal performance or fairness guarantee. CPU-efficiency optimization is deferred and is not a promotion gate for this increment; correctness, bounded queues and memory limits still apply. Each endpoint owns its sending controller and pacing budget, so configure both endpoints' caps for a symmetric comparison.

The wire profile is experimental and may change before release. The aggregate runtime currently depends directly on the Quinn carrier; a general carrier trait is still future work.

## Verification and interpretation

`cargo test --all-targets --locked` includes deterministic codec/record tests and real-socket three-entrance subprocess tests covering website access, wrong credentials, impaired relay traffic, integrity and relay removal. Deterministic adaptive tests cover repeated clean/congested/recovery transitions, idle/stale feedback, clock-drift diagnostics, transient buffer occupancy, byte-accounting units and application-limited traffic. These tests validate mechanisms, not WAN performance. CI runs on Linux, macOS and Windows; explicit interface binding is Linux-only.

Local Quinn sender tests additionally exercise writable wakeups without new input or timer events, cancellation without ghost sends, expiration and generation changes before admission, current group-credit checks, exact original/repair accounting, and bounded multi-flow delivery and shutdown.

Tunnel endpoints, relays, finite probes/sinks and the diagnostic echo process keep one interrupt future across receive loops and startup/workload transitions. A temporary `select!` wait borrows this future instead of subscribing again after each packet. A single SIGINT dispatched during another branch therefore remains pending for the next wait. The subprocess regression includes a recreated-listener negative control, and a real bidirectional UDP relay test requires one SIGINT to produce a normal exit, final statistics and exact relay counter conservation. This does not make blocked branch handlers preemptible or prove all possible shutdown failures are resolved; workload interruption and forced termination remain explicit failures.

`probe` supports echo and finite forward/reverse one-way measurements with `sink`. JSON reports loss, lateness, useful bytes, actual send span and unconditional P50/P95/P99; missing packets count as positive infinity, encoded as `"infinity"`. Echo uses monotonic RTT; one-way delay subtracts the minimum signed transit delta and is relative, not absolute. Select the ordinary UDP target directly for a raw baseline. Goodput includes the final observation allowance; measured rate and sender/receiver counts must be reconciled. Integrity failures, unavailable data and operational failures remain explicit. See [probe commands and interpretation](probe.md).

Relay `--drop-every N` deterministically drops every Nth permitted incoming UDP packet, including handshake/control traffic. It is a diagnostic packet-loss injector, not an independent random-loss model or a symmetric impairment model. Do not infer FEC benefit from a single run. Compare FEC-off/on, best single entrance and aggregation at the same application load and total budget, count both directions and backhaul cost, and include unequal RTTs, shared bottlenecks and outages. Follow the broader [validation gates](validation.md).

Test settings, credentials, private topology, raw captures and run results stay in ignored local directories. This runtime does not establish a default validated for filtered networks: stock Quinn fingerprints, TCP website parity/fallback, independent-peer interoperability and sustained deployment acceptance remain open.

## Machine-readable counters

For fixed-tuple comparisons, the client accepts one `--path-bind ADDRESS:PORT`
per interface–entrance pair, in the same path order as its interfaces and
entrances. Omit it for kernel-assigned ports. Binding failures are explicit; a
requested source port is used for the initial attempt. An adaptive retry or
explicit source-port rotation preserves the configured source IP and interface
but requests a new kernel-assigned port. Client path statistics record
`local_socket`; both endpoints record `peer_socket`, exposing the relay's
upstream mapping at the server. A repeated client port does not by itself prove
an unchanged relay-side tuple.

Client, server and relay support `--stats-file` for final JSON and optional `--stats-jsonl` / `--stats-interval-ms` for cumulative periodic samples. Readiness and failures are included so benchmarks can stop parsing logs. [Statistics schema and conservation boundaries](statistics.md) distinguish logical records, aggregate symbols, QUIC packets and relay datagrams. Run records belong under ignored `local/`.

`client --receiver-feedback` negotiates feedback version 2 with the authenticated peer. Sequence gaps, unique measured symbol bytes and delay variation are reported through bounded control datagrams, independently of FEC delivery. Delivery-rate samples use the receiver's report interval, not synchronized clocks or the spacing of feedback arrivals. This opt-in mode does not change data scheduling. Both endpoints must support the negotiated version; rejected negotiation is an explicit path admission failure. See [statistics](statistics.md) for counters, bounds and clock limitations.

`client --quality-schedule` enables receiver feedback and smooth weighted round robin in both directions. An estimate needs 16 finalized symbols and a report younger than 3 seconds; unknown/stale paths have weight 2. Healthy weight is `round(32 * (1-loss)^4 / (1 + (delay_variation_ms + quinn_rtt_ms)/50))`, clamped to 1..32. Every open path therefore retains an original-symbol probe share within the existing offered traffic and pacer. RTT includes both legs, so this heuristic does not claim absolute forward delay. Buffer-full paths are skipped using the existing admission behavior.

## Adaptive mode

`--adaptive` enables feedback, byte-weighted scheduling, per-path admission pacing and independent authenticated request/reply probes in both directions. It remains opt-in. Each new path generation starts with an allowance of at most 256 kbit/s and a bounded 2,400-byte burst. Exploration requires backlog and at least 90% actual use of the allowance. Allowed bytes are integrated using the rate active during each part of the control window, so a later rate reduction cannot make earlier admissions appear more fully utilized. The initial search also checks receiver delivery against admission. A low application-limited delivery sample does not establish a capacity ceiling.

Adaptive originals and repairs, including application echo traffic, also share a business pacer across paths. Each group's rate is the sum of its current live, eligible path allowances, limited by that group's configured cap. The aggregate rate is the sum of those capped group rates, limited by the configured session cap. A path waiting for its individual tokens still contributes its allowance; a closed or ineligible path does not. These are the controller's current sending budgets, not a new estimate of network capacity.

With fast byte feedback, ordinary-loss braking compares receiver service with actual admitted symbol bytes on complete paired windows. Both local-clock spans must cover at least 500 ms, the sender window must contain at least eight symbols under continuous demand, and it must start after the latest pace change. The observation must be at most 200 ms old. A short sender allowance interval cannot substitute for this admission evidence. Missing or mismatched evidence cannot authorize ordinary growth. The separate severe-loss, transport-blocked, queue and actual-delivery-deficit checks retain their own conditions; raw finalized loss is still reported.

The aggregate and each group receive a one-time initial business credit of at most 2,400 bytes, or a smaller configured burst allowance. The shared aggregate limits all paths and groups together to that initial amount. Their rates remain zero until eligible controller budgets are supplied, so credit alone does not allow a path to send. Elapsed time then earns credit at the previous rate before a new budget is installed. At high rates, sender buckets retain the greater of the original byte allowance and one millisecond of the current rate plus one maximum frame's credit. The extra frame preserves an earned remainder that cannot yet pay for a whole datagram; it creates no tokens. This matches the sender timer quantum without rounding each wakeup's service down to an integer number of packets. It applies to configured aggregate/group caps and learned business/path rates; the independent capacity-probe buckets retain their fixed byte bounds. A smaller rate immediately trims excess stored credit, and increasing a rate adds no tokens. Rate, eligibility, generation and membership changes cannot renew the initial credit or reprice past time; a regressed clock cannot accrue the same interval twice. This limits coincident business bursts across paths without removing the per-path or configured rate caps. The sender synchronizes budgets after observations and finite-trial grants, and after admission checks or successful accounting that can expire a trial. Immediate sends and writable-notification retries check both levels, and only successful Quinn acceptance spends the caller's existing encoded-length plus header allowance. Budget waiting does not count as a blocked QUIC transport. A millisecond of burst credit does not establish a millisecond of network delay or prove that the configured rate is achievable.

Protocol feedback and probe requests or responses retain the existing configured aggregate/group pacers and do not consume this additional business credit. They can therefore recover path health even when all eligible business budgets are zero. Fixed and quality-only modes do not construct or call the additional pacer. Its bounded burst and budget integral do not guarantee constant packet spacing, detect shared capacity, or establish an end-to-end deadline; transport ACK and handshake costs remain outside this application admission accounting.

A unique authenticated measurement sequence proves that its prefix was sent even when the peer's sent-count report is lost. The receiver starts the existing 500 ms reordering grace from that local arrival; a duplicate or reordered lower sequence cannot renew it. Sent-count reports still establish an unseen tail. At most four pending prefixes are retained: when full, only the newest entry is merged into a later prefix with a full grace, without forcing an older gap to retire early. The separate 512-sequence storage bound remains in force. Regular reports publish finalized loss; extra byte reports continue to carry the previous regular loss counts. This applies to both business measurement and independent probe measurement, without changing the wire format or application deduplication.

Adaptive senders can return extra positive-byte reports while business traffic is active. These require at least 4,096 newly received unique symbol bytes across the session paths and 100 ms since the previous report admission. An extra report is not constructed if the next regular report is less than 100 ms away, and does not postpone that regular 500 ms report. An extra report carries the latest cumulative delivered bytes and receiver-local clock, while retaining the previous full report's sent watermark, finalized counts and transit diagnostic. It therefore does not shorten the loss-finalization grace or refresh finalized-loss quality merely because bytes arrived. A new path sends a full report before using this abbreviated update. Fixed and quality-only scheduling keep the regular feedback cadence. All feedback retains the existing single pending frame and aggregate/group admission budgets. If transport blocking delays a pending extra report beyond the regular deadline, that overdue regular report may follow sooner than 100 ms once admission resumes; the clock does not discard pending work or delay the overdue report.

Ordinary congestion changes pacing while fresh health keeps a path eligible. The controller uses the latest authenticated probe RTT alongside current Quinn RTT, and bounded finalized-loss counts separately from diagnostic RTT/loss EWMAs. Persistent rising delay, corroborated loss or a demonstrated delivery shortfall can reduce the allowance. Repeated unchanged selected RTT is subject to the existing freshness, change and brake-spacing guards; estimator switching still has the limitation described below. Recently observed drainage and retained delivery support recovery: a pending drain recovery survives intermediate RTT observations until the next rate-control tick, which may restore up to 90% of a recent service hint. A short low-delivery report without exercised allowance does not establish a new capacity ceiling. An actual queue brake can also establish caution below 90% per-path allowance use when a recent paired business interval spans at least 500 ms, contains at least eight successful symbols and is entirely covered by uninterrupted observed backlog. Shared admission can limit a busy path below its own allowance. This qualification changes only congestion history, not the measured service or brake target; sparse or interrupted demand does not qualify. Bounded 25% steps every 200 ms revisit a previously exercised range, switching to at most 3% every 500 ms once within 90% of retained delivery. Initial supported growth normally remains capped at 50% every 400 ms. A positive byte report with an explicit receiver interval of at most 200 ms permits that same 50% gain at a 200 ms interval, only before congestion has been established and while the original demand, delivery and safety gates pass. Its locally observed report age and positive-delivery age must each be at most 200 ms; both report number and cumulative received bytes must advance beyond the report used for the previous initial-growth step. Reusing or replaying a short report cannot fund additional growth. A new generation resets this credit. Aggregate/group caps and actual admissions constrain every step.

Initial short-feedback search can retain one real positive report until the next control tick, so a qualifying report between ticks is not lost merely because the next short interval delivers fewer bytes. Capture requires a newer report and larger cumulative received-byte count, a finite positive interval of at most 200 ms, young positive evidence, eligible business backlog, no current pressure and wire-normalized delivery supporting at least 85% of the actual integrated allowance rate. Capture does not itself increase pacing or require the 90% exercise threshold. The newest qualifying report replaces the previous one; a lower but still positive report can retain the earlier credit without refreshing its timestamp. This is not a maximum over past delivery rates.

Before the first short-feedback increase, an unsuccessful control attempt retains its paired admission and allowance window while demand and fresh evidence continue without pressure. A late report can therefore qualify the first increase without waiting through another empty control period. Idle, pressure, an actual rate change or three seconds of accumulated history settles the window; legacy feedback keeps its previous cadence. Subsequent increases retain the original minimum spacing.

Consumption still requires the ordinary growth tick, actual 90% exercise, current 85% receiver support from the retained rate, fresh unused probe evidence and every existing pressure and cooldown gate. Both local age and captured positive age plus elapsed time must remain at most 200 ms. The observation must follow the latest pacing change, growth and brake boundaries. That local observation ordering does not prove that the entire receiver interval followed the change: the clocks and delivery phase are different. The report grants only one bounded initial step and never writes capacity memory or a drain hint. Actual pacing changes, caution, missing backlog, invalid or zero delivery, counter regression, observation gaps and expiry clear it. An initial no-op at a cap does not spend the report or create a growth event. `last_control.initial_delivery_credit`, omitted when absent, records the retained report number, cumulative bytes, local observation time, captured positive age and wire rate; its `used` flag identifies consumption by an actual increase. The current-report path and legacy 500 ms feedback behavior remain available.

After short feedback has been observed, ordinary initial and recovery growth consumes a new authenticated RTT probe whose response is at most 200 ms old and whose request began after the previous increase. The request's send instant is inferred from local response age and measured RTT. Drain restoration shares this one-use credit; missing probe evidence retains its pending restoration until the service hint expires, and successful restoration cannot stack another growth step on the same control tick. The separately qualified finite capacity trial described below retains its own rules.

Once congestion has been confirmed in this mode, ordinary growth and the old drain-hint fallback also need a completed service interval of at least 500 ms, observed locally after the last growth and at most 200 ms ago. An increase consumes that endpoint through the existing growth timestamp. Remembered delivery and a recent drain hint cannot fund repeated steps between new endpoints. Initial search and legacy feedback retain their existing rules. The independently qualified post-brake measured-service restoration below keeps its own service and probe qualifications.

In short-feedback mode, ordinary gains are bounded by the remaining queue headroom: `max(0, 0.8 * latency-target-ms - queue-delay-ms)`. Initial search divides that headroom by probe RTT. Monitored cautious growth also includes the 100 ms spacing between requests and any remaining wait before its first request. The resulting gain is capped at 50% and by the selected growth mode's existing limit. This accounts for the controller's observation horizon without identifying available capacity or guaranteeing a deadline; shared traffic can extend the actual delay.

A pending drain restoration can instead use one newly measured service interval after an actual brake. This exception still requires the control tick, fresh eligible path, no current pressure or protected trial, positive delivery at most 200 ms old, and the same unused young probe whose request began strictly after both the previous growth and latest brake. The latest service sample must have been observed locally within 200 ms. Its receiver and local admission intervals must each span at least 500 ms on their own clocks; the local interval needs at least eight successfully admitted symbols, positive admission rate, and uninterrupted observed backlog. Its first local endpoint must be at or after the latest brake and pace change, including trial rollback. A rollback during the current observation cannot qualify.

Unique receiver symbol delivery must exceed 1.1 times the actual admitted symbol rate over those paired intervals, corroborating drainage of earlier work. Only that latest sample can restore up to 90% of its wire-adjusted delivery rate, capped at the configured maximum; neither an older maximum drain hint nor the remembered capacity peak funds the exception. A real increase consumes pending drain and probe credit once and cannot stack ordinary growth on the same tick. `last_control.drain_service_target_bps` is present only for that actual increase and equals its final capped pacing target; the next observation clears it. Missing, stale or unqualified evidence retains the previous headroom-capped fallback. A measured target at or below the current pace does not enter the exception; the old fallback remains available. This compares intervals on independent clocks, not identical acknowledged packet cohorts; the wire conversion still uses the existing shorter actual admission-mix estimate and does not prove a guaranteed capacity.

By default, a further brake waits one current RTT (queue included) after the previous one: a queue reading still rising from pre-brake traffic is not new pressure. Severe queues (at least four times the target) and zero service keep the 100 ms spacing. A queue brake without loss or blocked-transport evidence, with backlog and a fresh delivery measurement, also records a drain-return target of 90% of that wire delivery. In short-feedback mode this includes a positive delivery-shortfall brake under the same standing queue; zero service still forgets the target. In that mode a new queue behind business backlog also sizes the brake from fresh delivery even when part of the allowance was unused, for example when the transport's own window limits sends after startup; the legacy rule kept a 20% cut per brake there, which could leave a deep startup queue growing for several RTTs. Repeated queue brakes within three seconds form one episode: its target never exceeds 90% of the pace before the episode's first brake, and a later fresh measurement replaces the target. While the queue still exceeds a quarter of the target, average delivery since the first post-brake report is the current bottleneck rate; at least 100 ms of it can only lower the target, so a capacity drop is not hidden by an older report. On the first control tick where a probe reply sent after the latest brake shows the queue at or below a quarter of the target, with backlog, fresh evidence and no pressure, loss pressure or protected trial, the path returns to that target in one step (`drain_return`) instead of waiting for the qualified 500 ms service window. The increase owns the ordinary growth monitor, so a rising queue withdraws it to the drained pace. Any other brake, a new generation or three seconds without return discards the target. A target at or below the current pace is a no-op, and the restoration above remains the fallback. After a monitored increase settles with neither a rising RTT nor a queue above a quarter of the target, the next cautious step doubles (3%, 6%, 12%, 24%, at most 48% per 500 ms, no faster than the initial search and still capped by the RTT headroom limit); any brake or withdrawal restarts it at 3%. `--legacy-recovery` disables all of these changes.

By default, loss alone does not reduce pacing while the path's queue delay is at most a quarter of the target and the transport has not stayed blocked for at least the target (minimum 100 ms). One datagram waiting in the send buffer at the sample instant is not a block. Such loss is treated as path loss: ordinary loss pressure, fast-loss brakes, positive-service deficit brakes and the ordinary-loss growth hold are suspended. Queue, sustained blocked-transport and zero-service brakes, and every cap, remain. The sender learns a loss floor from finalized intervals observed with a nearly empty queue (at most 5% of the target, minimum 2 ms): the lower median of recent 512-symbol buckets, capped at 50%. Buckets expire after 10 s of clear-queue time, not wall time: a queue cannot measure the floor, so it does not erase it either. Otherwise, after ten queued seconds the same path loss reads as a delivery shortfall in every report and brakes the path step by step toward the minimum pace. Every service and growth comparison sees delivery compensated by that floor and clamped to admitted bytes. In the loopback lab with 50% random loss on four paths, this keeps pacing at the offered-load bound instead of braking each path to the 64 kbps floor. A bottleneck that drops without queueing, such as a policer or a shallow buffer, would otherwise be overshot indefinitely; every drop is a hole that a reliable stream must repair an RTT later. So held loss more than 2 points beyond 1.5 times the path's known random loss (from 2 Mbit/s up) starts a rate-dependence test: the pace holds for three RTTs (at least 300 ms) and its loss is measured over two more (at least 200 ms, 512 symbols), then the pace drops to 3/4 and is measured the same way. Random loss stays the same at the lower pace; a path's own overrun keeps its delivered rate, so its loss falls to 1 - (1 - held) / 0.75 (or zero). Loss at most 40% of the way from that prediction to the held loss is the path's own; loss at least 60% of the way, and at most 1.2 times the held loss plus 2 points, is random and is forgiven for 30 s; anything else gives no verdict. Own loss that fell to a tolerable level caps the pace at 90% of the held pace; own loss that remains excessive caps it at the tested pace, and the next test goes lower. No test runs while the forward guard below tests or limits loss that most paths share, since the other paths take up whatever one path releases. A cap holds 10 s, then rises by 10% every 2 s while the pace presses against it. In the loopback lab, one 400 Mbit/s path at 110 ms whose emulator packet limit drops above about 160 Mbit/s without queueing, plus 0.5% random loss, lost 359,637 of 1,031,304 downstream packets to the limit before this test and 8,926 of 603,181 after, with 8,624 instead of 289,722 stream retransmissions; with 3% random loss and a deep queue the test found random loss and goodput was unchanged. `--legacy-recovery` restores loss brakes at any queue delay.

With business backlog, an eligible fresh path in short-feedback mode can request probes faster when its latest probe RTT is at most 200 ms. If the response is also at most 200 ms old, initial search, current pressure and an active finite trial retain the 100 ms request opportunity. Current pressure for this scheduling purpose includes nonhealthy state, queue above one quarter of the local target or transport blocking. Otherwise, cautious routine sampling uses the same young, unconsumed 500 ms service endpoint as ordinary growth. It requires at least 200 ms since the last successful request and that request to precede the endpoint's local observation time. Successful admission accounts for the request; a rejected request can be retried under the same existing budgets. Pending drain restoration alone does not request every 100 ms; a quiet pending path obtains evidence through the same endpoint, independent phase repair or health deadline. The pending state and measured-service restoration qualifications are unchanged.

This routine request can obtain new evidence while the previous response is older than 200 ms, provided it remains within the existing 3-second freshness bound and the current clock has not regressed before the recorded observation. The service endpoint itself must still be at most 200 ms old. Requesting a replacement does not refresh the old response or let it authorize growth: consumption still needs the original young, unused, strictly post-growth reply. When a control attempt has a young, unconsumed service endpoint but lacks the required probe reply, it keeps the paired admission/allowance window open. A returned probe can then use that completed window before the endpoint expires; neither evidence age nor the minimum spacing between actual increases is renewed. Idle, pressure, pace changes and endpoint expiry settle the window. A reply arriving after endpoint expiry still cannot authorize growth. Routine sampling no longer runs every 200 ms without a new endpoint; the independent monitoring, phase repair and 500 ms health deadline remain available.

For a newly authenticated native BBR path, the adaptive sender uses the current congestion window divided by the same RTT sample as its initial operational allowance, capped by the configured rate. This does not estimate capacity or add token credit. Missing window/RTT, current loss braking, blocked transport or queue pressure retain conservative startup. Each generation is initialized once; later observations cannot override a rate reduction. Every datagram still needs Quinn readiness plus aggregate/group/business budget and sender-age admission. Pure controller models without a native connection retain the 256 kbit/s startup. A `native_startup` rate event records the actual window and RTT used; capacity memory continues to require delivery evidence.

An actual ordinary increase after congestion starts one bounded growth monitor; independently probe-funded recovery is also monitored. Its requests start strictly after growth and respect the existing 100 ms admission spacing. The monitor stores two request/reply slots and expires three seconds after the original increase. After a confirmed first reply, a second request deferred by budget or transport retains its pending eligibility even if that reply ages past 200 ms; the existing spacing, RTT, health and three-second ownership limits still apply. Admitting the second request consumes its slot, so a missing reply creates no extra fast retries. An unsettled monitor prevents another ordinary increase. Initial search and separately qualified measured-drain restoration do not arm it; safety brakes and the other health/request opportunities remain independent.

The monitor collects distinct authenticated replies that were each at most 200 ms old when observed, with strictly advancing request origins after growth. Each reply retains the selected queue estimate at that observation. Withdrawal requires the second raw probe RTT to exceed both the first RTT and the pre-growth baseline by more than 0.25 ms. For a small excursion, both replies must show queue above one quarter of the target; a current queue above half the target can act without that additional persistence. All independent safety brakes run first. Withdrawal removes only the still-owned increment, records the usual brake watermark and cooldown, and creates no capacity or drain credit.

A withdrawal retains one bounded retry step for at most three seconds. The next ordinary increase from the exact same rollback baseline is capped at half the rejected increment, with the original service, probe, actual-use and cooldown requirements still in force. A successful pacing increase transfers that step to its new baseline and starts its own monitor. Only a pair that settles that retry without withdrawal can double the next step; an unfinished monitor cannot recover it. Another withdrawal halves the newly failed increment. Idle, stale or discontinuous observations, a new generation, an unrelated actual pace change or expiry discard the step. Confirmed monitoring renews its evidence time, but no-op ticks cannot. This prevents both repeating an unchanged failed gain and immediately restoring it after one smaller success, while allowing observed recovery to increase the step. Independently measured drain restoration remains unchanged. `last_control.growth_retry_ceiling_bps` records a cap when used and is otherwise omitted.

A rising pair that does not yet justify withdrawal keeps the current rate. Its newer reply becomes the next pair's first observation, allowing another spaced request without renewing the original three-second lifetime or recovering retry credit. A settled pair, withdrawal, loss of active backlog or fresh evidence, invalid time or generation, an observation gap, another pace change, or expiry releases the monitor. Expiry alone does not change pacing. `last_control.growth_monitor` records request times, RTT and queue observations, ownership and any actual withdrawal; a completed pair remains visible in that control sample. This is a pacing experiment with performance acceptance pending.

A cautious path also gets one independent phase repair when its last successfully admitted request is at or before the last growth timestamp: once at least 100 ms has passed since both growth and that request, it can ask for post-growth evidence even if the old response has aged past 200 ms. The old response must remain within the existing 3-second freshness, the active prerequisites above still apply, and the current clock must not precede the recorded observation. A newly arrived service window cannot cancel this repair. Only successful request admission consumes it; a budget or transport rejection does not. Without a returned reply, the path then falls back to the original 500 ms health deadline. A request never refreshes the old response or relaxes the young, unused, strictly post-growth reply required by actual growth. No request occurs within 100 ms of the previous successful request, and the existing 500 ms health deadline remains for every path. Idle, high-RTT, stale and probe-only operation retain that deadline and the four-nonce bound. The existing cautious no-op may conservatively cause an extra repair, but cannot create delivery evidence or authorize growth.

A young raw probe's excess over a separate running probe minimum can expose a startup queue before Quinn's smoothed RTT rises. It contributes to the queue estimate in that fast initial phase. A new rising probe at or above the target may invoke the normal bounded safety brake without another persistence interval. An excursion above half the target but below the target holds growth immediately and requires the existing 100 ms persistence before braking. A queue established this way survives the transition to caution until a new young probe observes the existing clear range or the evidence expires after 3 seconds; changing mode alone is not drainage. This minimum is per generation, does not establish queue-free propagation, and does not read the separate diagnostic minima.

Short byte intervals remain the initial receiver-keeps-up evidence. Once short feedback is observed, lasting service decisions instead use matching cumulative receiver endpoints spanning at least 500 ms: remembered delivery, drain hints, service-shortfall and ordinary-loss corroboration share that qualified service rate. Only a newly completed interval can renew capacity memory, a drain hint or a service-triggered brake; intervening reports cannot repeatedly spend the same service sample. The first endpoint only anchors the window. Two endpoints and one latest sample bound storage; intermediate sequence/time/byte regressions are rejected, a gap longer than 3 seconds clears the window, and a sample expires after 3 local seconds. Positive-byte health and finalized-loss processing still consume their own actual reports. Inputs that retain the original 500 ms cadence use their previous explicit-rate behavior.

A fresh qualified service interval also permits one bounded discovery step during cautious operation. An older disjoint interval that straddles a pace change cannot alone veto this step when a complete, fresh paired interval proves current service covers both actual admissions and the exercised allowance; independent pressure brakes remain in force. This requires queue delay at most one quarter of the target, no ordinary loss, positive delivery at most 200 ms old, and wire-normalized receiver service at least 85% of the exercised integrated allowance pace. The completed interval must have been observed locally after the previous increase and within 200 ms. Its arrival can precede the next control tick, but any intervening increase consumes that credit. The receiver interval can overlap an earlier pace; this is evidence to measure another bounded step, not proof of available capacity. The step uses the existing 25% recovery limit at a 200 ms control interval, subject to the RTT gain cap, new post-growth probe, brake retry and every ordinary safety gate. Congestion history remains set. When a new endpoint exists but these additional discovery conditions do not hold, the existing known-service recovery or 3% cautious search can use that endpoint under their own conditions. Without a new endpoint, ordinary growth waits. Statistics identify the discovery step as `service_discovery`.

A new qualified service window can also expose congestion while probes are lost or the allowance exceeds actual offered traffic. Its two local observation endpoints additionally capture authoritative cumulative successful symbol bytes and counts from the current Quality generation. The actual-admission rate uses the local observation interval; the receiver rate retains its separate receiver-clock interval. A service deficit can independently brake only when the local interval spans at least 500 ms, contains at least eight admitted symbols, starts at or after the most recent pace change including trial rollback, and is covered by a recent business-activity segment. The receiver symbol rate must be below 85% of the actual admitted symbol rate, and its wire-adjusted service must be below 85% of the current allowance. This evidence does not require high probe RTT or 90% allowance use; growth still does. A rollback during the current observation cannot qualify this branch.

For positive receiver service, the local interval must additionally start at least one complete selected RTT after the later of the activity segment's start and the latest actual pace change, or the current generation's start if no rate change has occurred. Missing or invalid RTT uses a 500 ms settlement period; the period is capped at the existing three-second freshness horizon before conversion to integer microseconds. These activity and actual-pace anchors remain fixed while continuous work proceeds at the same rate. Subsequent reports and capped growth attempts cannot renew this additional wait; the existing qualification and growth-timing conditions still apply. Detecting a persistent deficit also requires the next qualifying complete window and its returned report, not merely the settlement period. `service_admission.positive_settlement_since_us` records the additional wait's anchor separately from the existing `last_pace_change_us` timing guard. This bounds a startup or pace-transition phase mismatch without treating RTT as a strict upper bound on feedback delay or estimating a one-way delay from half an RTT. Zero service retains its original conditions and timing, and queue, blocked-transport and critical finalized-loss brakes remain independent.

In short-feedback mode, successful admission of positive business bytes or an observation with queued business refreshes this activity segment. A sampled empty queue does not erase recent successful work. Both entry points expire the previous segment before recording new activity: a gap of at least 200 ms, including the exact boundary, starts a new segment. Clock regression, generation change and an observation gap over three seconds also break continuity. Probes, control frames, failed sends, zero-byte callbacks and a configured but unused allowance cannot refresh it. Bursts separated by less than 200 ms can belong to one segment; this does not prove uninterrupted queue occupancy or network capacity. `service_admission.activity_since_us`, omitted when absent or outside short-feedback mode, records this qualification. The separate `backlog_since_us` used for measured drain restoration and the ordinary-growth backlog guard remain unchanged.

The paired deficit uses the existing delivery-shortfall brake, replaces an older drain hint with the new service, and enters caution after a real reduction. Positive measured service can guide the bounded target; zero service keeps the existing 0.8 multiplier and minimum pace. No new loss override, memory update or growth credit is added. Optional missing, invalid or decreasing sender coordinates invalidate only the paired evidence until re-anchored; the receiver-only estimator continues unchanged. These intervals do not prove identical in-flight cohorts or synchronized clocks. Their different transmission phase and the shorter wire/symbol conversion window remain measurement limits. Delivery exceeding current admissions can be legitimate drainage of earlier traffic.

Path shares also respond to fresh finalized loss when demand is too sparse to exercise a pacing allowance. The existing pacing/RTT base weight of 1..128 is expressed in 16 integer units per old unit, then multiplied by `(1 - effective_loss)^4`, bounded to 0.25..1. This limits the quality penalty to four times while preserving a positive original-symbol sampling share. A loss estimate qualifies only after at least 16 cumulative finalized symbols and a strictly newer valid, nonempty finalized interval with fresh loss evidence. Scheduling uses the authenticated loss EWMA with a separate bounded symbol-count constraint on recovery; the pacing brakes keep their existing evidence and thresholds.

The quality window retains the shortest suffix of whole accepted report deltas containing at least 16 finalized symbols. An oldest batch is removed only when the remaining batches still contain at least 16 symbols; reports are never split and loss positions are not inferred. This retains at most 16 nonempty batches. Once the window has at least 16 symbols, effective loss is the greater of the raw EWMA and the window's lost/expected fraction. Before that, the raw EWMA alone applies. This prevents a few sparse clean reports from restoring shares faster than their symbol evidence supports, while a higher raw loss estimate still takes effect immediately. Valid cumulative batches can populate the window before the 16-symbol maturity gate, but do not yet qualify a scheduling penalty. Legacy interval-only inputs cannot populate it.

Qualified evidence older than 3 seconds returns to a neutral multiplier. Before accepting a later valid batch, the window is cleared if its previous latest batch has aged beyond 3 seconds, including the age already present when observed. An oldest retained batch may exceed 3 seconds while later batches keep the window current; its separate age is reported. Repeated observations, invalid, empty or stale prefixes, byte-only progress and RTT probes cannot refresh the raw sample or window; a new generation resets both. With neutral quality, relative weights and clean scheduling order are unchanged. The final 4..2048 weight and its raw/effective loss evidence are recorded in the adaptive decision and used for byte scheduling. The retained share does not promise a fixed sampling interval at arbitrarily low offered traffic, and the recovery window does not establish a delivery guarantee.

Control evidence records the RTT inputs, selected value and source, mixed minimum, resulting RTT excess, transport wait, freshness and new-evidence flags at the observation associated with each rate change. Two additional per-source observed minima are diagnostic only; no pacing, weight, health, recovery or reprobe calculation reads them. They reset with the path generation and do not establish calibrated or queue-free propagation baselines. These diagnostic minima do not alter RTT selection, pacing or path weighting.

The current controller still selects an absolute RTT and subtracts a shared mixed minimum. With both inputs available, it uses the smaller numeric RTT while a probe is at most 100 ms old, or while Quinn has not risen by more than 0.25 ms and the probe is at most 500 ms old; otherwise it prefers current Quinn. Existing single-source fallbacks remain. Consequently, a fixed offset between Quinn's smoothed estimate and raw probe readings can become apparent queue pressure when the selected source changes. The new evidence exposes this behavior but does not correct it. Probe age measures time since receipt, and its RTT can cover an earlier queueing interval. Neither these diagnostics nor the original selector solve temporal fusion or identify a queue already present at startup.

Loss evidence uses cumulative finalized expected/lost integers from the authenticated path feedback. Only a strictly newer report with fresh finalized-loss evidence contributes a nonempty delta; skipped observations recover the cumulative difference without inventing extra report batches. The history retains at most eight nonempty batches for four seconds after observation. That horizon does not assert when the underlying packets were sent, and the batches are not assumed to be statistically independent. Ordinary evidence requires at least two observed batches, at least 64 finalized symbols and a loss fraction strictly above 5%, compared with integer arithmetic. A newest batch of at least eight symbols with at least 50% loss still permits immediate safety braking; the separate all-loss reachability rule below is unchanged.

Positive byte delivery and finalized-loss freshness are tracked independently. A strictly newer authenticated report can update receiver service while its positive delivery is fresh, even if no recent sequence prefix has finalized. A valid but stale cumulative loss prefix advances the baseline without adding or refreshing loss evidence, so a later report cannot count that old prefix again. All-loss reachability decisions and pressure-episode retirement still require fresh finalized-loss information. Increasing report numbers alone cannot renew the timestamp of positive delivery or revive a silent path.

Ordinary loss affects pacing only when independent receiver service is below 85% of the integrated allowance pace, actual admissions exercised at least 90% of that allowance, and the pace has not changed for at least 600 ms. Finalized loss and current receiver bytes describe different cohorts; their counts are never combined into one sample population. Credible loss with poor current service pauses further growth while that evidence settles, including recovery toward retained capacity. This prevents faster recovery steps from continuously postponing the service check. The integrated allowance also provides the receiver-keeps-up reference, so a short token-credit burst cannot manufacture a higher capacity demand. Raw loss diagnostics remain visible; adaptive `loss_evidence_expected`, `loss_evidence_lost`, `loss_pressure` and `cautious` expose the control evidence and mode. Adaptive health describes qualified control pressure and reachability, rather than a promise of loss-free delivery.

Immediate safety braking is separate from entering persistent cautious exploration. In short-feedback mode, the first actual reduction in a pressure episode records whether admission used at least 90% of the integrated allowance; a transient that never brakes cannot occupy this snapshot. Starting short feedback discards only an uncommitted legacy snapshot. Legacy cadence retains its first-pressure-observation rule. An effective brake enters persistent caution when that original episode was exercised and current delay, transport blocking or settled service shortfall provides capacity evidence, or when the new paired actual-admission deficit independently qualifies. Filling a smaller allowance after a brake cannot retrospectively qualify the episode. A delayed severe loss batch alone does not qualify persistent caution. Each brake in caution records the higher of the wire rate delivered at that brake and the pace it set, keeping the highest since caution began. An RTT spike on a lightly loaded path, for example, can put the path into caution far below what it can carry, and cautious steps then take tens of seconds to reach that capacity. Therefore, when an ordinary increase reaches twice that recorded rate with queue delay at most a quarter of the target, and the latest delivery is at least 1.5 times it, caution ends and the path resumes the initial search. A path braked at its real capacity cannot deliver 1.5 times it, so caution stays; the next brake starts it again. Episode retirement requires both clear current pressure and a genuinely new finalized loss interval that does not trigger qualified loss pressure. A clear RTT on an old report alone does not retire it.

Short feedback also distinguishes evidence generated before a brake from evidence that can demonstrate continuing overload. A moderate queue carried only by a probe whose request began at or before the previous brake keeps growth paused without independently repeating the reduction. A new post-brake request, selected or rising Quinn pressure, transport wait and severe queue retain their ordinary delay-brake response. For finalized loss, the controller records the authoritative successful symbol count at each actual congestion reduction. A wholly older batch cannot independently repeat fast-loss braking; a straddling batch must prove at least eight new symbols and at least 50% loss after subtracting the maximum loss attributable to its older portion. The severe-queue exception keeps the existing four-target queue threshold and additionally requires severity in its current contributing component: Quinn RTT itself above the existing mixed minimum by at least four targets, transport wait itself at least four targets, or a newly observed fresh probe whose request began after the previous brake and whose own selected or current startup excess reaches that threshold. A retained severe probe cannot supply the exception again, and a small unrelated local change cannot validate its severity. A high smoothed Quinn RTT alone cannot create an exception while the selected queue is below the severe threshold. Blocked transport and exercised settled service shortfall retain the raw fast-loss safety rule; the separate paired actual-admission deficit brake is unchanged. Missing or invalid cumulative coordinates also keep the raw rule. Raw loss, health hold, trial rollback and scheduling weights remain unchanged; a new generation clears the boundary. See `brake_loss` in the statistics reference for the exact qualified evidence.

When an observation has no business backlog, no exercised allowance, no persistent transport blocking and no qualified paired actual-admission deficit, RTT or loss changes update quality and health without shrinking the unused allowance. A qualified deficit can enable the existing safety brake even when the current queue is empty and allowance use is below 90%; eligibility and the brake timing gate still apply. A low delivery sample can directly set a lower pacing target after the pressure episode was exercised, a new exercised delivery shortfall is demonstrated, or the paired actual-admission deficit qualifies; otherwise reductions use the existing bounded multiplicative rule. This prevents sparse traffic from being interpreted as a small measured capacity. It does not allow growth through persistent excess RTT, and an instantaneous queued record can still constitute backlog at an observation.

Reachability evidence is positive received-byte progress on the path or a valid authenticated probe reply. Finalizing missing symbols refreshes loss information but cannot extend the positive-delivery timestamp, even when a healthy alternate path carries the report. After the startup grace period, positive evidence older than 3 seconds makes a path probe-only. An earlier exclusion applies when a fresh finalized interval contains at least 8 symbols, all are lost, received-byte rate is zero, and neither positive delivery nor a valid probe has occurred within 500 ms. That exclusion persists until new positive evidence arrives; its timing also depends on loss finalization and feedback delivery. Positive delivery or a valid probe reply can restore business eligibility immediately. Same-generation recovery retains learned pace and delivery history; a new path generation resets that controller and starts a new search.

With `--fec 0 --redundancy-percent 0`, a busy path with low excess RTT can qualify for receiver-service-validated exploration after loss or stalled growth. Qualification requires two seconds of actual admission evidence. The controller first measures a stable baseline, then requests up to a 50% allowance increase. Baseline, waiting and trial phases are each bounded to four seconds; a delayed control observation cannot extend trial-rate token credit beyond its deadline. Measurements settle for at least one second, twice RTT and twice the latest receiver report span before taking a new receiver-local anchor. At least three fresh report intervals spanning 1.5 seconds must show exercised allowance. A full 50% trial must increase unique symbol service by at least 20% before the higher pace is retained. No absolute clock comparison or compressed feedback-arrival interval is used to infer service.

A change in the actual pacing allowance invalidates a trial before delayed receiver reports can certify it. Any remaining unvalidated increment is withdrawn to at most the previous baseline; an already lower safety rate is preserved. Service measured at the old trial pace cannot establish successful recovery at a different pace.

These bounded measurement phases temporarily defer ordinary loss reductions so unchanged erasure does not undo every trial. Excess RTT above half the local target, severe new loss, sustained transport blocking, stale feedback or lost health aborts exploration and preserves the existing safety brakes. New trials and successful validation require excess RTT no higher than 40% of the target. A successful pace is held while fresh receiver service remains supported; another trial needs current exercised demand. Idle demand cannot establish reduced capacity. Failure returns to no more than the baseline allowance, with retry backoff from two to thirty seconds. Only one trial per explicitly configured bottleneck group can be active and grants rotate across paths. New trial credit is granted only when it fits the current live-path aggregate and group headroom. Actual admissions always remain subject to their pacers; independent ordinary growth does not promise that the sum of controller allowances stays below those caps. A removed or replaced path cannot retain a trial grant. This exploration is disabled with FEC or redundancy because raw symbol delivery would not establish increased unique application service.

Exploration must not take over a normal recovery that is already increasing pace. Low-queue demand qualification accumulates continuously, but entering the baseline phase additionally requires currently qualified loss pressure or a stalled controller and at least two seconds without ordinary pacing growth. A brake does not reset that continuous demand qualification. A clean-service exit returns control to ordinary growth and braking when at least three distinct fresh, nonempty finalized-loss reports cover at least 32 symbols, span at least one receiver-clock second and show no more than 2% loss. A settled receiver service window of at least 1.5 seconds must also keep up with at least 85% of the operational allowance, using the cost ratio from the same recent actual-admission window; that allowance must be at least 90% exercised. The entire receiver service window must begin at or after the first clean report's receiver-local endpoint, so earlier high delivery cannot supply the recovery proof. Low queue and fresh health remain required. This exit does not erase loss history or jump directly to remembered capacity. An unfinished trial first withdraws its unvalidated extra allowance. Idle, dirty or stale evidence cannot be joined into a clean-recovery proof.

Adaptive senders observe accepted full/delivery feedback and valid probe replies through a coalesced notification owned by the sending actor. All paths in that sender share one pending notification; other senders and fixed mode do not participate. Rejected or replayed feedback, probe requests and ordinary business arrivals do not create observation notifications. Every actual observation is at least 1 ms after the previous one. An earlier event remains pending until the existing heartbeat can consume it, and backward time does not consume pending work. The first observation and each periodic observation schedule the next fallback for 100 ms later; extra evidence observations do not move that deadline. Coincident evidence and periodic work produces one observation, without replaying missed periods. This removes an avoidable periodic wait after valid feedback, but does not remove network RTT or guarantee a maximum queue delay.

Ordinary delay still needs at least 100 ms of persistence before a delay brake; a large increase can be acted on immediately at an observation. Fast initial search also acts on the new rising probe evidence described above. A successful nonempty business admission interrupts the continuous transport-blockage timer: repeated full-buffer snapshots cannot establish uninterrupted blocking across actual service. This grants no capacity or growth credit; delay, loss and actual-admission deficit brakes retain their checks. Rate reductions occur no more often than every 100 ms; growth uses the unchanged intervals above. RTT probes normally use 500 ms per path, including while business traffic is idle, with the bounded 100/200 ms active short-feedback opportunities and one post-growth phase repair described above. All probes require aggregate/group budget and room in the path's local budget; feedback and RTT probes go ahead of queued business datagrams in the path's writer. Probe requests and replies do not enter FEC or application delivery; unmatched, replayed, expired or wrong-generation replies cannot refresh health. A healthy feedback route is preferred over silent paths. Deferred feedback reserves aggregate budget and budget in one usable group. Both business traffic and probes respect that reservation, preventing continuous small records from consuming every feedback opportunity.

The measured cross-clock transit minimum remains diagnostic. Adaptive congestion decisions use local-clock RTT evidence and buffer pressure; a rising cross-clock value alone cannot cause downshift or elective rotation. Observed delivery counts measured symbols before application processing, and the pacing allowance is an operational budget. The bounded Quinn buffer contributes a sustained-blocking signal. Its current size falls below the controller's transient-burst allowance, so it does not contribute an occupancy-derived waiting-time estimate.

A path's RTT can wander on its own, through cross traffic or route jitter, by more than the brake threshold, and braking cannot reduce that delay. Without a discount, every rise above the threshold brakes such a path, and the path stays at the 64 kbit/s floor. That floor does not lower latency. When a path has been paced at or below 256 kbit/s for at least two RTTs (and at least 400 ms), and its RTT excess has since fallen to half the target or less, any queue it built earlier has drained. Its RTT excess samples from then on are wander. The upper decile of those samples over the last 20 seconds is subtracted from later queue readings; it needs at least 16 samples and is capped at four latency targets. A queue this path adds on top of most of its wander therefore still brakes at the target. Between 256 kbit/s and 1 Mbit/s a path also learns, but only while its delivery over the latest service interval (at least 500 ms, ended within the last second) is at least 85% of what it admitted, and each such sample counts at most one latency target. A bottleneck slower than the pace queues and underdelivers, so its queue is not learned this way. Above 1 Mbit/s a path learns nothing new, because its excess may include its own queue. The discount it keeps halves every 60 seconds and shrinks with every baseline refresh. A bottleneck at or below 256 kbit/s would have its own queue learned as wander, up to that cap. Control evidence records the discount applied as `rtt_wander_ms`.

The per-generation minimum RTT has no time-based aging: above the light pace, a propagation change that does not survive the standing-delay test can remain classified as excess delay. Retained delivery can also cause bounded upward trials after a permanent capacity reduction. Pressure-episode retirement has a separate limitation: a new clear finalized interval does not prove that every loss from before or during the episode has been finalized, because no sequence watermark ties that interval to episode onset. A later loss report can therefore start another episode. The cold-pause regression does not establish a universal startup cure; delayed feedback, baseline refresh and long-running behavior require further validation.

The default 20 ms target applies to local sender age and the added-delay control objective; admission uses local age alone. Native probes report 100 ms and 150 ms arrival buckets using the complete requested count, including missing and unsent operations. Echo buckets use monotonic application RTT; bulk buckets use relative one-way delay. A prospective run must declare its primary threshold before launch. Selecting 150 ms does not change queue admission or rewrite the original controlled-scenario protocol, which retains its 100 ms clean/recovered 95% and impaired 90% interactive objectives and matched-goodput requirements. A longer run may additionally report recovery, steady and fixed-duration cohorts, while retaining its full-run denominator. These are workload-specific validation objectives, not a hard cross-host SLA or a claim that the candidate passes.

Example with the local main server and relay above:

```bash
./target/release/braidpath client --listen 127.0.0.1:7000 \
  --entrance 127.0.0.1:7443 --entrance 127.0.0.1:7444 \
  --server-name localhost --ca local/identity/cert.pem \
  --token-file local/identity/token --adaptive --latency-target-ms 20 \
  --rate-bps 10000000 --path-group 0 --path-group 0 \
  --group-rate-bps 0:8000000
```

This assigns both entrances to one explicitly capped group. By default, all entrances on the same configured interface share a group; default-route paths all belong to group 0. With two interfaces and two entrances, path order is interface 0/entrance 0, interface 0/entrance 1, interface 1/entrance 0, interface 1/entrance 1. Repeated `--path-group` values override that mapping. Group caps constrain combined admitted traffic; they do not discover physical independence or prove congestion-control fairness against other traffic.

### One-way bound on the queue signal

Queue delay is RTT above its minimum, so it also contains the reverse direction: an acknowledgement direction's probe replies and ACKs wait behind the peer's own bulk queue, and a delay step in the reverse direction looks the same. Braking this direction cannot drain either, and an acknowledgement direction braked to its floor for them starves its requests. The receiver already measures this direction's one-way transit above its own minimum and reports it. While such a report is at most 1 s old, the RTT excess used for queue decisions is at most that one-way excess plus 2 ms. The bound only lowers the RTT signal, so clock drift between hosts cannot create congestion; without a fresh report the RTT signal is used unchanged. `--legacy-recovery` disables the bound.

### Reverse load on an asymmetric uplink

A bulk sender makes its peer send acknowledgements in proportion: native QUIC ACKs, reliable-stream ACKs and their copies. When every route leaves the peer through one small uplink, for example a client whose upload is a fraction of its download, that reverse load can exceed it. A direct-drop policer then discards the peer's requests and ACKs without queueing delay, so delay-based pacing sees no congestion, while interactive requests wait for retransmission. Three defaults reduce the load, and a guard bounds the remainder:

- Runtime endpoints ask the peer to acknowledge every eighth ack-eliciting packet, within a requested 10 ms (`--ack-request every-eight`, a server flag; the client asks the same of the server). Quinn otherwise follows every second packet. `--ack-request unchanged` and the client's `--legacy-recovery` keep Quinn's behaviour.
- A reliable stream receiver acknowledges by segment count (16) at most every 4 ms; duplicates, FIN and empty frames are acknowledged at once, and isolated short segments keep the 2 ms delay. Each acknowledgement repeats its ranges, so count-driven acknowledgements alone could reach several Mbit/s at a high download rate.
- Stream ACKs take at most one proactive copy at any FEC level; the next ACK supersedes them.
- In adaptive mode each sender also guards a bottleneck shared by the forward paths. Two of three 500 ms windows with loss shared by two thirds of connected paths (100 finalized symbols each), at least 5% or 4 points above a learned floor, from 2 Mbit/s, start a 10%-40% aggregate rate cut. The trial compares estimated delivery (send rate times one minus aggregate finalized loss) before and after the cut; retaining more than half the delivery that would otherwise have been lost confirms a cap. A rejected trial learns rate-independent loss. Every cut waits until every connected path's finalized prefix has passed its local admission watermark at the cut. Initial trials decide from two subsequent qualified windows immediately, without an extra blind timer. A trial window may close after 100 ms when at least 1024 new finalized symbols and the normal per-path quorum are available; thin feedback keeps accumulating at the ordinary 500 ms cadence. The pre-cut watermark must still pass on every connected path; decreases of an already kept cap also wait at least 2 s. Only subsequent report intervals qualify; sender and receiver clocks are never compared. A trial without enough qualified feedback ends inconclusively after at most 10.5 s and cannot raise the floor. Kept caps cut by 5%-30% on excess loss, and learn unchanged loss as a floor only when post-cut actual sending also fell by at least 5%. Clean binding caps grow by 5% below 95% of the most recent overrun rate, and by 1% at or above it; crossing that rate cannot restore fast growth. Ten seconds below half the cap release it. Per-path loss trials pause while shared loss is tested or limited. A rejected aggregate trial that actually reduced sending by at least 5% while exercising at least 80% of its cap also seeds each qualified path's existing 30 s random-loss cache once. Each path uses the smaller of its own before/after loss observations (at least 100 finalized symbols each, same generation), so a clean route cannot inherit another route's loss. This avoids repeating the same rate experiment on each path; extra loss, queue and service protections remain active, and replacement generations clear the cache. Direction statistics expose `forward_guard`, including `settling` and `growth_threshold_bps`. `--legacy-recovery` disables it. This remains a heuristic, not a capacity measurement. Historical loopback measurements of the earlier guard, not validation of these settlement changes: four paths at 85 to 92 ms behind a 90 Mbit/s direct-drop policer with 11% random loss lost 33% to the policer without that guard and 3.6% with it, at 64.3 and 63.6 Mbit/s; with 5% random loss, 5.3% instead of 4.7%, at 65.0 instead of 65.4 Mbit/s.
- In adaptive mode each sender tracks finalized loss of the symbols it receives back from the peer, per path, in 500 ms windows. Each decision uses the loss that at least two thirds of the connected paths reach (three of four paths), counting only paths with at least 100 reverse symbols in the window, so that one lost symbol cannot reach the onset loss. Steady loss on one or two routes therefore does not count, nor does a path without enough symbols to measure, while a shared uplink, which drops on all of them, does. When that loss is at least 5% (or 4 points above a learned floor) for two windows while this direction sends at least 2 Mbit/s, a trial caps this direction's aggregate pacer at 70% of its measured rate. The cap stays only if reverse loss falls by at least half; otherwise that loss is recorded as a rate-independent floor, which follows steady loss and decays once it goes away, and the trial is not repeated for 20 seconds. A kept cap decreases by 15% (from the lower of cap and measured rate) on renewed reverse loss, at most every other window, since the window after a decrease still carries the earlier reverse load, and grows by 5% per clean window only while the measured rate reaches 80% of it; ten seconds with the rate below half the cap open the guard again. `reverse_guard` in the direction statistics shows the cap, trials and decisions. `--legacy-recovery` disables the guard. This is a heuristic for one shared uplink, not a capacity measurement, and it does not change per-path controllers or native congestion control.

## Path and session recovery

Adaptive mode retries initially unavailable and disconnected paths, including an all-path outage. There is at most one attempt per path and two attempts across the client at once. Attempts have an 8-second deadline; consecutive failures back off from 2 s to at most 60 s. A newly disconnected path remains recoverable after a successful connection; a lifetime attempt counter cannot permanently disable it. Each retry preserves interface, entrance and explicit source IP, while selecting a new source port.

`--rotate-source-port` additionally permits elective replacement of an open degraded path and requires quality scheduling or adaptive mode. The legacy quality criterion uses at least 32 finalized symbols, fresh forward feedback and 4 continuous seconds with loss above 5% or transit variation above 100 ms. Adaptive mode corroborates the delay criterion with local RTT-probe evidence. Return-only degradation does not independently trigger this client-side elective policy. An initial connection does not spend the elective cooldown; a successful elective rotation starts a 30-second cooldown. Replacement can discard in-flight old-generation datagrams, which remain losses.

Before a path is excluded or replaced, the sender withholds data from a path
whose ack-eliciting QUIC frames have gone unanswered for `max(2·RTT + 25 ms,
100 ms)` and resumes on its next ACK ([path liveness](reliable-streams.md#scheduling));
this applies to UDP records and streams alike, in every mode.

Generation numbers increase within the authenticated session. The server keeps one highest admitted generation per path, rejecting replay or regression without an expanding history. Old-handler cleanup cannot remove its replacement. During a short all-path outage, session and record identity remain intact. If the server has expired its empty session or restarted, it rejects rejoin explicitly; the client then creates a fresh session ID and resets that epoch's flow/record state while retaining the local UDP listener. This is an explicit new epoch, not replay of already delivered records or reliable delivery across the outage.

Paired fixed-load observations, availability failures, port histories and unconditional latency must be reported before considering a default change. Multi-interface capacity, shared-bottleneck competition, long-running field behavior and deployment reachability remain separate acceptance gates. Automatic FEC is implemented and enabled by default; automatic bottleneck detection, coupled congestion control and Reed–Solomon/sliding-window coding remain deferred.

A measured drain restoration requires both receiver and local admission intervals of at least 500 ms and at least eight actual admitted symbols. A fresh disjoint sample lacking either admission floor does not hide a newer qualifying paired interval. The existing post-brake, unchanged-pace, continuous-backlog and young unused reply checks apply to that interval too. Before a complete post-brake interval exists, fresh cross-brake drainage can hold the first speculative step for at most the existing three-second horizon. No average packet size substitutes for actual admissions.

An underfilled actual admission/allowance window may remain pending for up to 500 ms while otherwise eligible fresh evidence remains available, including while a growth monitor awaits settlement. With a currently qualified independent probe-service reference, a pending monitor retains the same unchanged-pace window within that bound even after actual use reaches 90%; meeting the exercise floor does not start a new pacing interval. Without that reference, an exercised ordinary window retains its original settlement behavior. Keeping the window does not allow growth before the monitor settles or before the original 90% actual-use requirement is met. Pressure, idle demand, stale evidence and generation or pace changes still settle the window.

In probe-guided recovery, current independently corroborated erasure uses the expected retained fraction for scheduling instead of the fourth-power penalty. This applies only while the existing covered-loss classification, qualified owned reference covering business pace, control observation, positive business progress and RTT are current within200ms. Unknown startup loss, missing/expired measurement and uncovered loss keep the original policy. Both multipliers remain0.25..1; weights remain4..2048. Statistics expose weight_erasure_corroborated. This changes relative service shares and creates no pacing or capacity credit.

The sender's reachability check uses the native driver's published ACK-frame,
ACK-eliciting-frame and RTT hints. It does not acquire the QUIC connection lock
while holding the path list. The 5 ms check cadence, 100 ms minimum silence,
2 RTT plus ACK-delay bound, and all-path-silent fallback are unchanged.
